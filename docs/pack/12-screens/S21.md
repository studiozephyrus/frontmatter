## Purpose

See every version of this document, who or what wrote each one, and put an older one back.

## Entry and exit

Direction | How | Route or control
In | The history row in the right rail, which shows the retention window | `C035`
In | An accepted item on S20, which links to the version it made | S20
In | The overflow control on the toolbar | `C077`
Out | Restore, which writes the old bytes as a new version and returns to the document | S04
Out | Copy as a new document, which leaves this one alone | S04, on the new file
Out | Export the history, which downloads a folder of files | A download
Out | Over the retention window on Free | S33

**Restoring never rewinds.** It writes the old bytes forward as a new version, so the version that
was current when you pressed it is still there afterwards.

## Data contract

What | Direction | Port or store | Shape | When
Version list | read | `VaultReader.listHistory(path, limit)` | `VaultHistoryEntry` of `{ sha, message, author, date }` | On open
Version body | read | `VaultReader.getFileAtSha(path, sha)` | The bytes at that version, or null when it is not a readable file | When a row is chosen
Diff | derived | In the browser, from the two bodies | Lines marked as context, removed or added | With the body
Attribution | read | `VersionRecord.forDocument(documentId)` | `{ author, source, model, ask, accepted_by, at }` | With the list
Restore | write | `ProjectFiles.splice` | The old bytes written forward as a new version | On restore
Copy as new | write | `ProjectFiles.create` | A new document holding those bytes | On copy
Export | read | `ExportHistory.zip(documentId)` | A folder of files, one per version | On export
Entitlement | read | `limitsFor(account)` | `limits.history.days` | On open, to set the window and the pill

**Part of this is built, and it reads a different store from the one the plan specifies.**

What | Where it is at `0af3c90` | What the plan says
The port | `VaultReader.listHistory` and `getFileAtSha` in `src/modules/vault/application/ports.ts:27` and `:33` | Unchanged
The use cases | `src/modules/vault/application/get-history.ts` and `get-version.ts` | Unchanged
The routes | `src/app/api/vault/history`, `/version` and `/restore` | Unchanged
The store | Git commits on a GitHub vault. `VaultHistoryEntry` carries a commit `sha` and a commit `message` | A version is an R2 object keyed by document id and content hash, at `docs/mvp0/PRODUCT-PLAN.md` section 18

**That gap is the screen's largest risk.** Commit history is per repository, so it gives no retention
window per account, no per-version attribution beyond a commit author, and nothing for a document
that is not in a connected repository. The retention window, the plan badge and the three author
kinds all need the version store, not the commit log.

**Attribution survives here.** The per-span read state of the earlier plan was dropped, and what
replaced it is the mark in the version record. This screen is where a person sees it.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Open the history | The rail row, or the toolbar overflow | The list loads, newest first, and the newest is selected | Store unreachable, so `E105` and the rail row shows the reason | `doc.history.opened`
Choose a version | Click a row, or Enter on it | Its body loads and the diff against the current version is drawn | Body not a readable file, so `E105` names the row and draws no diff | `doc.version.viewed`
Restore | The restore control | The old bytes are written forward as a new version, attributed to you | Splice refuses, so `E026`, and nothing is written | `doc.version.restored`
Copy as a new document | The copy control | A new document is created holding those bytes. This one is untouched | Over the document cap, so `E070` sends to S33 | `doc.version.copied`
Export the history | The rail foot control | A folder of files downloads, one per version | Too large to build, so `E504` offers a date range | `doc.history.exported`
Reach the end of the window | Scrolling past the retention window | The list stops and says how far back this plan keeps versions | none | `doc.history.window.reached`

**Nothing on this screen deletes a version.** Pruning happens on its own schedule, against the
retention window, and never as a result of anything a person does here.

## States

State | When | What is shown | What the person can do
first-run | The first time history is opened on this account | One line naming the window this plan gives | Read it, then browse.
empty | A document saved once | One row, the creation, with no diff to draw | Read, write more.
loading | The list is being read | The rail shape renders, rows fill in | Wait.
partial | The list is in, a body is still loading | The list is usable. The diff area shows its shape | Choose another version.
offline | No connection | Versions already fetched are readable. Restore and export are disabled with one reason | Read, come back.
unauthorised | The role has no history right | The row is absent. The matrix at `docs/mvp0/PRODUCT-PLAN.md` section 19 governs it | Ask the owner.
over-cap | The account dropped to a shorter window | Versions inside the new window stay. Older ones are named as out of window, never as deleted, until pruning runs | Export, or go to Pro.
AI-unavailable | n/a. History calls no model | n/a | n/a.
conflict | The document changed while a version was being viewed | The diff is redrawn against the new current version, and says so | Re-read, restore, or go to S31.
error | A body failed to load | `E105` on that row. The list stays usable | Choose another version.
degraded | More versions than the list can usefully show | Grouped by day, with counts, newest first | Expand a day, or export.

## Keyboard and focus

key | does
Tab, Shift Tab | Moves through the list, then the two controls, then the export control
Up, Down | Moves between versions without leaving the list
Enter | Loads the focused version into the diff
1, 2, 3, 4 | Moves the filter to All, People, AI or Agents, while focus is in the panel
Escape | Closes the panel and returns focus to the document

**Focus on arrival is the newest version row.** It is already selected, so arriving by keyboard costs
no travel.

**Restore is never one keystroke from arrival.** It is a write, and it sits after the list in the tab
order for that reason.

**The diff is a list of lines with their kind in the accessible name**, not colour alone. Added and
removed lines carry a leading marker in the text as well.

**Checked 18 September, no collision `[O]`.** File 15 names S21 only in its section 8, rule 2, as the
place to go past undo, and binds nothing to it. Up, Down, Enter and the digits act only inside the
panel. Escape closes the panel, the topmost layer, per its section 5.

- **Restore has no key**, and it must not get a bare one: it writes, and file 15 section 1 rule 2 keeps
  writes off bare keys.
- The overflow control on the toolbar is the pointer route. File 15 does not list these keys yet,
  recorded in the log for its owner.

## Responsive

- **The list comes first** at phone width, with the diff under it and the two controls at the foot,
  as drawn at `docs/mvp0/screens/gen.mjs:1405`.
- **The diff scrolls sideways** rather than wrapping, because a wrapped diff line reads as two
  changes.
- **The export control moves into the overflow**, since a phone is a poor place to take a download of
  a whole history.
- **Nothing is unavailable at phone width.**

## Desktop differences

- **Export writes into a folder on disk** rather than downloading, because the desktop build has the
  file system.
- **A document in a watched folder has a local history too**, and the list says which store a version
  came from when both exist.
- Everything else is identical.

## What this screen must never do

- **Never delete a version.** Pruning is the retention window's job, on its own schedule.
- **Never rewind.** A restore moves forward.
- **Never guess an author.** Show what the version record says, or show that it is unknown.
- **Never draw a diff by colour alone.**
- **Never hard-code the retention window.**
- **Never say a version is gone when it is merely outside the window.**
- **Never let a copy-as-new touch the source document.**

## Open questions

id | question | why it is open
`D51` | Whether the shipped commit-log history is phase A's answer, or whether the R2 version store lands first | The port reads git commits today and the plan specifies content-hashed objects, at `docs/mvp0/PRODUCT-PLAN.md` section 18. A document outside a connected repository has no history at all until that is settled.
`D52` | What pruning does at the window's edge: prune to the head, or keep a daily version | The plan says pruned to the head at `docs/mvp0/PRODUCT-PLAN.md` section 18, which loses every intermediate version, and no screen says so to the person.
`D53` | Whether restoring a version restores its attribution or attributes the restore to the person doing it | This file says the second, because the person made the choice. Nothing in the plan decides it.

**Resolutions.** None of these is `[Z]`.

- **`D51`, resolved (proposed 18 Sep, founder review).** The R2 version store lands first, in phase A.
  `D03` makes our copy canonical and the person's repository a mirror `[Z]`, so a commit log is the
  mirror's history, not ours, and it cannot serve a document outside a repository.
  - The shipped port and routes are kept as the interface. Only the store behind
    `VaultReader.listHistory` changes, to the version collection of `21-DATA-MODEL.md`.
  - Rejected: the commit log for phase A, which leaves every non-repository document with no history.
- **`D52`, resolved (proposed 18 Sep, founder review).** Prune to the head, as the plan's section 18
  and `21-DATA-MODEL.md` say, and say so on the screen before it happens.
  - `K.s21.window.end` and `K.s21.outofwindow` already carry the words, and export is offered beside
    them, so nobody loses a version they wanted without a way to keep it.
  - Reason: full-copy history is the one cost line that compounds, which the data model quotes from
    plan section 15, and a kept daily version would turn a 7-day window into an unbounded one.
  - Rejected: keeping a daily version past the window.
- **`D53`, resolved (proposed 18 Sep, founder review).** The restore is attributed to the person who
  pressed it, with `source: person`. Its `parentVersionId` and message name the version restored.
  The old version keeps its own attribution on its own row.
  - Reason: the record says who acted. Copying the old mark forward would say an AI wrote something now, which it did not.
  - Rejected: restoring the original attribution. `K.s21.restored` already tells the person the restore is theirs.
