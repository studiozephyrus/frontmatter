## Answers

**A.** The market puts both controls on paid tiers: Dropbox (Professional and up, not Plus), Figma (password on any paid plan, expiry Enterprise only), Loom (Business and up), Google (expiry only, Workspace editions, never personal). The two exceptions are security products: Bitwarden gives password and deletion date to free users for text. Notion has no password at all. Recommendation: expiry free (it costs nothing and reads as good hygiene, Bitwarden's default 7 days is a sensible default), password paid. That matches every document tool opened and leaves a clean upgrade reason.

**B.** Import: `<input type="file" webkitdirectory>` everywhere (Chrome 7, Edge 13, Firefox 50, Safari 11.1, iOS 18.4, Chrome Android 132), plus drag-and-drop via `webkitGetAsEntry()` on desktop. Write-back: only `showDirectoryPicker({mode:"readwrite"})` on Chrome and Edge (Chromium 86, Android 132); BCD records `false` for Firefox, Safari and iOS. On those, `createWritable()` exists (Firefox 111, Safari 26) but only reaches OPFS, because no directory picker exists. So: Chromium gets a live folder, everyone else gets a one-way import and downloads or Drive/GitHub for the way back.

**C.** Limits: Chrome ~60% of disk per origin, Firefox min(10% of disk, 10 GiB) best-effort, Safari ~60% since macOS 14/iOS 17 (1 GiB then prompt before). Safari deletes all script-writable storage after seven days of Safari use without visiting the site; an installed home-screen app is exempt. `persist()` is silently decided by Chrome/Safari on engagement and installation, and prompts in Firefox. Background Sync and share_target are Chromium-only. The one rule: never let the browser be the only copy. Write every keystroke to IndexedDB or OPFS, call `persist()` inside a user gesture, and push to a server, Drive or GitHub at the first connection; on Safari treat storage as a cache.

**D.** Feasible with `drive.file` alone: `changes.list` and `files.watch` accept it, and the Picker grants per-file access. Real constraints: `changes.watch` channels die after a week (file channels after a day) with no automatic renewal, notifications carry no content, so the app polls `changes.list` from a stored page token anyway. Cost at 30 saves: 30 × 50 (`files.update`) = 1,500 units per user per day (1,650 with a `files.get` per save), against 325,000 units per user per minute; a five-minute `changes.list` poll adds 288 × 100 = 28,800 units per day. The 400,000,000 daily project threshold covers 400,000,000 / 1,500 = 266,666 users at 30 saves before Google's still-unpublished billing applies.

**E.** Request repository "Contents: read and write" (the Contents API and Git access require it) and nothing else; add "Workflows" only if a user's vault contains `.github/workflows`. Use a GitHub App so the user picks specific repositories, tokens expire hourly, and the installation gets its own 5,000 to 12,500 requests per hour instead of eating the user's personal budget. Send the file's blob `sha` on every update and handle 409 by re-reading; this maps directly onto the splice-only CAS rule.

**F.** Follow the union of the two: Account (profile, emails, security, delete), Preferences (appearance, language, time zone, links open in desktop), Notifications, Editor (default view, line length, spellcheck), Files and links (default folders, attachments, link format, trash), Workspace (name, members, export, delete), Connections (Google Drive, GitHub), Sharing and security, Plans and billing, Hotkeys.
