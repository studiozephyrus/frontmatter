# S01. Sign in

> The front door. Nothing behind it is reachable without an account, and the door itself costs
> one tap.

> **Ids invented here.** `14-COMPONENT-INVENTORY.md`, `16-COPY-DECK.md`,
> `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md`,
> `55-MEASUREMENT-AND-EVENTS.md` and `56-OPEN-DECISIONS.md` are being written in parallel and did
> not exist when this file was written. Ids follow `65-CONVENTIONS.md` section 3 on a stated
> scheme derived from the screen number: components `C010` to `C019`, errors `E010` to `E019`, acceptance `A010` to `A019`. A component owned by another screen
> is cited by that screen's id. Copy ids are namespaced `K.s01.*`, so they cannot collide.

## Purpose

Let a person into the product in one tap, with no password to invent and no puzzle to solve, while
the page behind the card shows what they are signing in to.

## Entry and exit

Direction | Route or control | Goes to | Notes
Arrive, signed out | `/login` | this screen | `src/app/(auth)/login/page.tsx` renders it today
Arrive, redirected | any gated route while signed out | `/login` | `src/proxy.ts` performs the redirect
Arrive, from a published page | Edit on S18 | `/login` | the sign-in boundary is editing, never reading
Leave, Google | `K.s01.google` | provider popup, then `/` | S02 on a first account, S03 after
Leave, GitHub | `K.s01.github` | provider popup, then `/` | same
Leave, Privacy | `K.s01.privacy` | `/privacy` | serves without an account
Leave, Terms | `K.s01.terms` | `/terms` | serves without an account
Leave, provider list | `K.s01.providerlist` | the model-provider page | the page that makes the training promise checkable
Leave, already signed in | automatic | `/` | a signed-in session never sees this screen

**There is no third way in.** No email and password field, no magic link, no single-sign-on box.
The email magic link is a flag in the configuration panel and is off for phase A.

### The two brand marks, in detail

This is a founders' instruction and it has a failure mode, so it is written as a rule rather than
as a preference.

Mark | Source file | Delivery | Colour
Google | `docs/mvp0/screens/icons/brand-google.svg` | inline SVG, four `<path>` elements | the four brand fills carried in the file, `#4285F4` first
GitHub | `docs/mvp0/screens/icons/brand-github.svg` | inline SVG, one `<path>` | `fill="currentColor"`, so it follows the theme

- **Both are inline SVG in the markup.** No icon web font, no `<img>`, no CDN, no sprite sheet.
- **The Google mark keeps its own fills** and is never recoloured to the accent or to currentColor.
- **Brand marks are not Material Symbols** and do not come from that set. `65-CONVENTIONS.md`
  section 9 carries the rule.
- `docs/mvp0/screens/gen.mjs` has a `brand()` helper that strips `height`, `width`, `style` and
  `class` from each path and keeps `fill`. The built screen should follow the same shape.

### The phone panel

The founders' review of 18 September called the phone view bland and asked for the same theme
treatment as the desktop. The review's own note says it is a theming instruction rather than a
layout one, so the phone keeps one column and gains the surface, the type and the spacing tokens
the desktop card uses. No new controls appear on it.

## Data contract

What | Direction | Port or store | Shape | When
Sign-in with Google | out | `AuthGateway.signInWithGoogle()` | `Promise<AuthUser>` | on tap
Sign-in with GitHub | out | `AuthGateway.signInWithGitHub()` | `Promise<AuthUser>` | on tap; **specified, not built**
Session restore | in | `AuthGateway.observeUser(cb)` | `AuthUser \| null` | on mount, fires once when the SDK settles
Redirect target | in | query string on `/login` | a path string | on mount
Profile record | out | account store | account document, created once | first successful sign-in
Theme preference | in | device storage, then the account | `light \| dark \| system` | on mount, before first paint

- `AuthGateway` is the real port and lives at `src/modules/auth/application/ports.ts`. Its
  `signInWithGoogle`, `signOut`, `currentUser`, `observeUser` and `getIdToken` members are built.
- **`signInWithGitHub` is not on the port yet.** It is specified here and has to be added.
- The screen reads no document, no vault and no workspace. It cannot, because there is no session.
- `observeUser` returns `null` before the initial token restore, so the buttons stay enabled and the
  screen never blocks on it. A restored session navigates away.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Continue with Google | tap `C015`, or Enter on focus | opens the provider popup, then creates or restores the session | popup blocked `E011`; user cancelled `E012`; provider refused `E010`; offline `E013` | `auth.signin.started`
Continue with GitHub | tap `C016` | as above, GitHub provider | same four | `auth.signin.started`
Session created | provider returns | writes the profile record, then routes to `/` | profile write failed `E014`, and the session is discarded rather than half made | `auth.signin.succeeded`
Sign-in failed | provider throws | the card stays, the reason is named on the card, both buttons stay enabled | the error id is shown, never a raw provider string | `auth.signin.failed`
Open Privacy | tap `C017` link | `/privacy` in the same tab | route unavailable `E015` | `auth.legal.opened`
Open Terms | tap `C017` link | `/terms` in the same tab | `E015` | `auth.legal.opened`
Open the provider list | tap `C017` link | the model-provider page | `E015` | `auth.providers.opened`
Already signed in | `observeUser` fires with a user | replaces the route with `/`, no flash of the card | none | `auth.session.restored`

**A cancelled sign-in is not an error to apologise for.** `E012` returns the person to the card
with nothing said beyond the card's own copy.

## Keyboard and focus

- **On arrival, focus is on the Google button.** Not on the page body and not on a heading.
- Tab order: Google, GitHub, provider list, Privacy, Terms. The preview panel is inert and takes no
  tab stop.
- Enter or Space on a focused button starts that provider.
- Escape while the popup is open returns focus to the button that opened it.
- No screen shortcut is registered here, so there is nothing to conflict with the global map in
  `15-INTERACTION-AND-KEYBOARD.md`.
- The focus ring is visible on both buttons at the contrast the token set already asserts.

## Responsive

- **Under 900 px the preview column is dropped**, not stacked. The card takes the full width.
- The value strip moves under the card and becomes three stacked rows.
- Tap targets stay at the Material minimum, which section 12 of the plan records as the number that
  governs phone sizing.
- Nothing on this screen is unavailable at phone width. Both providers work.

## Desktop differences

The Tauri build opens the same screen. Two differences.

- The provider flow uses the system browser and returns by the app's protocol handler, because a
  popup inside the shell cannot complete an OAuth redirect reliably.
- A signed-in session is restored from the app's own store before first paint, so the desktop app
  usually skips this screen entirely.

## What this screen must never do

- **Never show a captcha, a puzzle, a bot check or a tour.** This is a standing founders' rule and
  it has no exception for abuse, for a provider outage or for a launch.
- **Never ask for a password**, and never render a password field, even hidden.
- **Never use an emoji, a web icon font or a second icon library for the two brand marks.**
- **Never recolour the Google mark.**
- **Never gate `/privacy`, `/terms` or the provider list behind sign-in.** They are the pages that
  make the fine print checkable.
- **Never make more than one tap stand between arriving and the provider popup.**
- **Never show a raw provider error string.** Name the error id from
  `17-ERROR-AND-REFUSAL-CATALOGUE.md`.
- **Never block the card on the preview panel.** A degraded preview shows the card alone.
- **Never write anything to a document store from this screen.** It has no session.
