title: Authentication
status: draft
owner: amit
tags: [auth, github-app, security]

Authentication

We use the GitHub App installation flow rather than an OAuth app, because the App grants permission per repository instead of across the whole account.

Token lifetime

The installation token is scoped to the repositories the user selected and expires after one hour, which means a leaked token has a bounded blast radius. Refresh happens transparently on the next request; the user never sees it.

If the installation is revoked, the next call fails cleanly and we surface it once, rather than retrying silently and appearing broken.

What we never do

  • Ask for the repo scope. It grants everything; the App asks per repository.
  • Store the installation token anywhere but memory. It is re-minted from the App's private key on every cold start, and the private key lives in the secret store, never in an environment variable that a crash dump could print.
  • Keep a second identity path. Two auth paths is two session-fixation surfaces for one operator.

Open questions

Should the consent screen ask for one repository at a time, or let the user multi-select? Asking for less converts better but adds a step for teams with many repos.

title: ADR-0004 Sync without a CRDT
status: proposed
date: 2026-09-02

ADR-0004 · Sync without a CRDT

Context

Two devices edit the same markdown file. Most sync products reach for a CRDT because convergence is guaranteed. Convergence is not the property we want: CRDTs interleave concurrent edits character by character, so two people finishing the same sentence produce a merged sentence neither wrote.

Decision

Git three-way merge, with divergence surfaced as a reviewable conflict. On the same inputs it preserves Windows line endings and a missing final newline, and it stops exactly where a careful writer would want to stop.

Consequences

  • Conflicts happen, and users hate conflicts. We publish the conflict rate as a shipped metric with a budget.
  • We never guess which version was meant. That is the whole point.

title: Pricing
status: decided
tags: [pricing, obsidian, teams]

Pricing

The editor is free. Obsidian settled that: the whole editor at $0, sync at $4, a $50/user/year commercial licence. Everyone priced around it.

What we charge for

  • Team — $8/user/month. Provenance across a shared repo, review state across people, admin.
  • Sync — $4/user/month, later, when it is provably safe.

The arithmetic

At $8/seat, 114 paying seats covers the monthly nut of ₹1.09L — about twenty small teams. Churn on a team licence is far lower than on a personal one.
