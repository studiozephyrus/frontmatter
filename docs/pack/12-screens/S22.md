## Purpose

Bring documents in from wherever they are now, keeping markdown byte for byte and saying plainly what
could not be kept.

## The instruction this screen exists to satisfy

**Upload has to be obvious.** The founders gave it on 18 September, at
`docs/mvp0/SCREEN-CHANGES-2026-09-18.md:178`, and left the placement open. The answer accepted in
section 8.1 has four parts, and all four are needed together.

1. **Add file opens a menu**, holding New document, Upload files, Upload a folder and Import from, at
   `docs/mvp0/SCREEN-CHANGES-2026-09-18.md:232`. Upload lives inside a button that had to exist, so
   no third button competes with the two the founders named.
2. **The whole workspace is a drop target**, at every moment, with the hint always visible in the
   tree.
3. **The empty states carry the words.** S02 on a first-time home and S34 on an empty ideas tab say
   in plain words that a folder can be dropped, because that is the only moment a person is looking
   for it, at `docs/mvp0/SCREEN-CHANGES-2026-09-18.md:236`.
4. **This screen is the full surface**, reached from Import from, with a large drop area and the six
   sources listed.

**One button, a drop target and words in the empty state.** No modal, no wizard, and no third button.

**The six sources, and what each one is.**

Source | What it takes | What it does
A folder | A directory from the machine | Keeps the structure and becomes a project. An Obsidian vault imports as it is
GitHub | A repository | Its docs, with write-back, through the connection on S23
Google Drive | A folder you pick | Stays in sync, through the connection on S23
Google Docs | A document | Converted to markdown on import
Word | A `.docx` file | Converted in the browser, so the file never leaves the machine
Notion | The export zip | Imports as a project

## Data contract

What | Direction | Port or store | Shape | When
Chosen files | read | The browser's file input, or the drop event | A list of files with their relative paths | On choose or drop
Folder structure | read | The directory input, or the entries interface on a drop | The tree under the chosen root | On choose or drop
Word conversion | derived | In the browser | Markdown, from the `.docx`, with nothing uploaded | Per file, before any upload
Markdown files | write | `ProjectFiles.create` | The bytes, unchanged | Per file
Attachments | write | `Uploads.put` | The bytes, under the project | Per non-markdown file
Obsidian settings | read | The `.obsidian` folder | The daily-note path and the templates folder, and nothing else | Once, per vault
Progress | read | `ImportRun.progress(runId)` | `{ done, total, kept, uploaded, needsLook, refused }` | Throughout
Entitlement | read | `limitsFor(account)` | `limits.docs.cloud`, `limits.uploads.total`, `limits.uploads.file` | Before each write

**None of this is built.** At `0af3c90` there is no `src/modules/import/`, no `mammoth` dependency
and no directory input in `src/`. The nearest shipped thing is `upload-attachment.ts` in
`src/modules/repository/application/`, which takes one file. The screen is **specified, not built**.

**What the browser allows, and where it stops** `[M]`, from the plan at section 11.

Capability | Where it works | Line
Reading a folder in | Chrome 7, Edge 13, Firefox 50, Safari 11.1, iOS Safari 18.4, Android Chrome 132 | `docs/mvp0/PRODUCT-PLAN.md` section 11, at line 994
Dragging a folder in | Desktop, through the entries interface | section 11, at line 995
Writing back to the person's own folder | Chrome and Edge only, and not baseline | section 11, at line 996

**So every browser imports, Chromium browsers can keep a live folder, and everyone else gets Drive,
GitHub or a download for the way back.**

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Open the menu | Add file, anywhere in the workspace | Four items appear, of which two are upload | none | `import.menu.opened`
Upload files | The second menu item | The file picker opens, multiple selection allowed | A file past the per-file cap, so `E038` names it and the rest continue | `import.files.chosen`
Upload a folder | The third menu item | The directory picker opens | Browser has no directory input, so `E380` offers file selection instead | `import.folder.chosen`
Drop | Files or a folder, anywhere over the workspace | The same run as Upload a folder begins | Drop carries no readable entries, so `E381` asks for the picker | `import.dropped`
Choose a source | A card in the grid | That source's flow starts, which may hand off to S23 | Source unreachable, so `E382` names it and the others stay | `import.source.chosen`
Convert a Word file | A `.docx` in the selection | Converted in the browser to markdown, with nothing uploaded | Conversion fails, so `E383` keeps the original as an attachment and says so | `import.word.converted`
Refuse a Google Doc | An export past 10 MB | `E035`, which names the limit, the actual size, and what to do | none | `import.gdoc.refused`
Read Obsidian settings | A `.obsidian` folder in the chosen root | The daily-note path and the templates folder are read. Nothing else is touched | Unreadable, so it is skipped silently and the import continues | `import.obsidian.read`
Finish | The last file | The panel totals the four outcomes and the rail foot opens the project | Over the document cap mid-run, so `E070` stops and sends to S33 | `import.run.finished`
Cancel | Cancel, during a run | The run stops. Everything already written stays | none | `import.run.cancelled`

**`E035` states the number.** A refusal that does not say why is not a refusal, it is a failure. The
limit, the actual size and the remedy all appear on the row.

## States

State | When | What is shown | What the person can do
first-run | An account with no documents | The drop area and the six sources, with the words in the empty state | Drop, choose, or pick a source.
empty | Nothing chosen yet | The same screen. This screen has no empty list to show | Drop, choose, or pick a source.
loading | A run is starting | The panel appears with its shape and a zero count | Wait, or cancel.
partial | A run is in flight | The meter, the running count, and the outcome rows filling | Watch, open what has landed, or cancel.
offline | No connection | Files convert in the browser and queue locally. Nothing uploads until the connection returns | Choose, convert, wait.
unauthorised | A source's authorisation was refused or withdrawn | That card is marked and the reason given. Other sources still work | Reauthorise on S23, or choose another.
over-cap | The run would cross a cap | `E070`. What already landed stays. Nothing new is created | Delete, export, or go to Pro.
AI-unavailable | n/a. Importing calls no model | n/a | n/a.
conflict | An incoming file matches an existing path | Both are kept and the newcomer is suffixed. Nothing is overwritten | Rename, merge by hand, or delete one.
error | A file fails for any other reason | It is counted in the needs-a-look row with its own reason | Open it, retry it, or leave it.
degraded | A source is rate-limited | The run slows and says so. It does not fail | Wait, or cancel and resume later.

**An import never overwrites.** A path collision keeps both, because the person importing has not
been asked which one they meant.

## Keyboard and focus

key | does
Tab, Shift Tab | Moves through the drop area, the six source cards, then the progress panel
Enter, Space | Activates the focused card, or opens the picker from the drop area
Escape | Cancels a picker, never a run in flight

**Focus on arrival is the drop area**, which doubles as the file picker when activated by keyboard. A
drop target that can only be reached with a mouse is not a control.

**A run in flight is announced politely**, with the count updating in a live region that does not
interrupt. The four outcome rows are announced once each, when they first appear.

## Responsive

- **Four source cards rather than six** at phone width, as drawn at `docs/mvp0/screens/gen.mjs:1426`. GitHub and Drive
  are reached from S23 instead, because both need an authorisation flow that suits a settings page.
- **The drop area becomes a chooser.** A phone has nothing to drop from.
- **The share sheet from another app** lands in the same place, on Android and after the app has been
  added to the home screen. **iOS has no share target for a web app**, and the phone card says so in
  plain words rather than showing a control that will not work.
- **The progress panel moves under the page** rather than into a rail.

## Desktop differences

- **A folder can be watched rather than copied.** The desktop build has the file system, so an import
  can leave the files where they are and keep them in sync, which is the thing the browser's
  write-back cannot do outside Chromium.
- **The drop target includes the dock icon.**
- **No document cap applies**, so `E070` cannot fire on the desktop.

## What this screen must never do

- **Never overwrite an existing file.** Keep both.
- **Never convert markdown.** It goes in as it is, front matter and all.
- **Never upload a Word file.** It converts on the machine.
- **Never refuse without the number.** State the limit, the actual size and the remedy.
- **Never read more of a vault than the two settings named.**
- **Never add a third creation button** to the left rail.
- **Never show an iOS share control that cannot work.** Say so instead.
- **Never leave a browser without a directory input stuck.** Offer file selection.
- **Never lose what already landed** when a run is cancelled or stopped by a cap.
