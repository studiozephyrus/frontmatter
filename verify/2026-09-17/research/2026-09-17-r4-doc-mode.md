## 2. What markdown can hold

**CommonMark 0.31.2** (`spec.commonmark.org/0.31.2/`) has sections for thematic breaks (§4.1), ATX and Setext headings, indented and fenced code, HTML blocks, block quotes, lists, code spans, emphasis, links, images, autolinks, raw HTML, hard line breaks. Raw HTML: "Text between < and > that looks like an HTML tag is parsed as a raw HTML tag and will be rendered in HTML without escaping." Hard break: "A line ending ... preceded by two or more spaces and does not occur at the end of a block is parsed as a hard line break". Images: "Syntax for images is like the syntax for links, with one difference." No size, wrap, or caption attribute exists. The words strikethrough, superscript, subscript, highlight, task list and YAML occur zero times; footnotes and tables appear once, historically: "Some extended the original Markdown syntax with conventions for footnotes, tables, and other document elements."

**GFM 0.29-gfm** (`github.github.com/gfm/`): "GFM is a strict superset of CommonMark." Five extensions: tables (§4.10), task list items (§5.3), strikethrough (§6.5), autolinks (§6.9), disallowed raw HTML (§6.11, filters `<title> <textarea> <style> <xmp> <iframe> <noembed>` and more). Tables have "a single header row", "Block-level elements cannot be inserted in a table", colons in the delimiter row give "left, right, or center alignment", and "If there are greater, the excess is ignored". No merged cells, widths, or captions. **Footnotes are not in the GFM spec**; GitHub's docs (`docs.github.com/.../basic-writing-and-formatting-syntax`) separately say "You can add footnotes to your content by using this bracket syntax".

**Pandoc** (`pandoc.org/MANUAL.html`): `footnotes` (`[^1]`), `inline_notes`, `task_lists` ("using the syntax of GitHub-Flavored Markdown"), `definition_lists`, `pipe_tables`, `multiline_tables` ("the table parser pays attention to the widths of the columns, and the writers try to reproduce these relative widths"), `table_captions` ("A caption is a paragraph beginning with the string Table:"), `implicit_figures` ("An image with nonempty alt text, occurring by itself in a paragraph, will be rendered as a figure with a caption"), `link_attributes` (`{#id .class width=30 height=20px}`), `header_attributes`, `fenced_divs` ("at least three consecutive colons plus some attributes"), `bracketed_spans` (`[This is *some text*]{.class key="val"}`), `superscript`/`subscript`, `strikeout`, `mark` (`==`), small caps (`{.smallcaps}`), underline (`{.underline}`), `yaml_metadata_block` ("delimited by a line of three hyphens (---) at the top"), `raw_tex` ("Inline TeX commands will be preserved and passed unchanged to the LaTeX and ConTeXt writers"). Its page-break example is a raw block: "This can be useful to insert raw xml into docx documents, e.g. a pagebreak" followed by `{=openxml}`; a `\newpage` via `raw_tex` is my inference from the sentence above, not a quoted example.

## 3. What the rich editors do

**Tiptap** (`tiptap.dev/docs/editor/extensions`): free extensions cover FontFamily, FontSize, Color, BackgroundColor, LineHeight (all "inline style" spans), TextAlign ("adds a text align attribute"), Highlight (`<mark>`, "Type ==two equal signs=="), Underline, Strike, Subscript, Superscript, Table (`mergeCells()`, `splitCell()`, `toggleHeaderColumn()`, `resizable`; cell colour not documented on the page), Image (`inline` option; `resize` gives "a resizable node view"), TaskList ("Type [ ] or [x]"), Mention ("@mentions"), Mathematics (KaTeX), TableOfContents, FindAndReplace, CharacterCount. Paid: Comments ("Available in Start plan"), Pages ("Available in Team plan", "provides proper margins, page breaks, and layout controls"), Tracked Changes ("Paid add-on Alpha ... all edits appear as proposals that can be accepted or rejected"), Snapshot (versions), Export/Import ("docx, odt, and markdown", Start plan, beta). No standalone page-break extension appears in the roster. Its Markdown extension (`/docs/editor/markdown`) is "a early release", built on MarkedJS, and lists two limitations: "Comments are not supported yet ... may be lost if replaced by Markdown content" and "only one child node per cell is allowed as the Markdown syntax can't represent multiple child nodes".

**Typora** (`support.typora.io`): "Typora tries to follow GitHub Flavored Markdown, but may still have small incompatibilities." Live preview: "Markdown tags for inline styles, such as ** will be hidden or displayed smartly." Superscript, subscript and highlight each say "please enable it first in the Markdown tab of the preference panel". Fonts: "Custom fonts in Typora are set by CSS." Spacing: "Typora uses CSS to control spacing." Images: "Currently Typora does not support image alignment. But you can use HTML code like `<center>![img](src)</center>`"; sizing uses `<img width="200px">` or `style="zoom:50%"`. Page breaks: `<div style="page-break-after: always; break-after: page;"></div>`. HTML limits: "class, id, and data-* are also not supported" and "exporting to other formats, such as Word or LaTeX, their HTML content may become plain text." Export page lists PDF, HTML, Image, Word (.docx), OpenOffice (.odt), RTF, Epub, LaTeX, reStructuredText, Textile, OPML.

**Bear Lettera** (`blog.bear.app/2026/06/...`, `lettera.md`): "Lettera follows the CommonMark standard with live rendering. Markdown syntax hides when you are not editing"; features "tables, quotes, lists, code blocks, inline images and attachments, Math formula with Mathjax". Neither page states any limit of WYSIWYG markdown.

**Milkdown** README: "A plugin-driven WYSIWYG markdown Editor, inspired by Typora, built on top of prosemirror and remark." **tui.editor** README: "Markdown mode and WYSIWYG mode, which can be switched any point in time"; plugins `table-merged-cell` ("You can merge columns of the table header and body area") and `color-syntax` ("change the color of the editing text with the GUI"), both outside CommonMark/GFM. **Obsidian** (`Views and editing mode.md`, permalink `edit-and-read`): "Live Preview shows formatted text inline while hiding most Markdown syntax. When your cursor enters formatted content, the underlying syntax becomes visible"; "Source mode displays all Markdown syntax exactly as written." Its Flavored Markdown page adds `==highlight==`, `[^id]`, `%%comments%%`, `> [!note]` callouts, and "Obsidian does not render Markdown syntax inside HTML elements."

## B. Not representable, with the honest substitute

- **Page breaks, section breaks:** a `---pagebreak---` marker (or Typora's `<div style="page-break-after: always">`) honoured only by PDF/DOCX export.
- **Headers, footers, page numbers, margins, orientation, watermarks:** front-matter keys read only by export.
- **Columns, pages mode, pinned header rows, text wrap around images:** none in the file; the export theme may apply them.
- **Merged cells:** refuse (Pandoc and GFM both lack them); split into rows, or an `fm-table` fenced block that renders here and prints as a plain table elsewhere.
- **Cell colours, borders, padding; custom bullet glyphs; spacing, indentation, tab stops:** theme-level only.
- **Crop, drawings, linked charts:** save the edited image and embed it.
- **Smart chips, dropdowns, building blocks, tabs, tasks, meeting notes, eSignature, AppSheet:** Google's own rule, "Smart chips change to text or links"; tabs become files or H1 sections.
- **Comments, suggesting, version history:** the review sidecar keyed by content hash, git diffs, git tags.
- **Publish to web:** export plus a host.

## D. Scope recommendation

**Ship, lossless:** headings, bold, italic, strikethrough, links, block and inline images, bullet, numbered, nested and check lists, GFM tables with column alignment and inline-only cells, block quotes, code, thematic breaks, hard breaks, Unicode symbols, plus the tools that leave the file alone: find and replace, word count, spelling and dictionary, translate, voice typing, templates, offline, export.

**Ship with a visible "renders here, exports to PDF, plain elsewhere" note:** `==highlight==`, `^sup^`/`~sub~`, `[^footnotes]`, `$math$`, image size `{width=}`, `Table:` and figure captions, heading ids for bookmarks, `[toc]`, front matter for title, subtitle, author, date and every export-only page setting, `{.underline}` and `{.smallcaps}`, citations if Pandoc's syntax is adopted. Keep raw-HTML colour, font and alignment spans out of the default toolbar: Google removes them on `.md` export and Typora warns they become plain text in Word and LaTeX.

**Refuse:** everything in B.

Refusal rule: doc mode carries a feature only if a stranger's plain CommonMark parser, with no editor and no export theme, still shows the author's meaning from the bytes on disk; anything whose meaning lives in pagination, live data, or editor state is refused rather than approximated in the file.
