# S42. PDF to Markdown

> **Where the ids come from.** Every `F`, `C`, `E`, `A`, `D` and `K` id below lives in its register,
> and every event in `55-MEASUREMENT-AND-EVENTS.md` section 6.14. This file first carried placeholders;
> they were allocated on 19 September, and `tools/new-ids-allocation.md` maps each one. The error ids
> and events are the same ones `72-PDF-TO-MARKDOWN-SPEC.md` sections 8 and 14.4 carry.

> **What this screen draws.** The converter, the output contract, the flags, the caps and the PDF's
> life belong to `72-PDF-TO-MARKDOWN-SPEC.md`, built on the research at
> `docs/research/2026-09-19-pdf/PDF-TO-MARKDOWN.md` section 6. This file says only how a person meets
> them. Where the two disagree, `72` wins and this file is the one to fix.

## Purpose

Turn a PDF into markdown I can edit, see what the converter was unsure of before I take it, and know
the PDF itself is not kept.

## The rules this screen carries

- **One converter, three doors.** An empty document, the AI panel while editing, and a standalone
  tool that files into notes. Each shows the same preview; only where the result lands differs
  (`72-PDF-TO-MARKDOWN-SPEC.md` section 4).
- **The PDF never leaves the machine** on the text path or the browser OCR path, and the screen says
  so where the file is chosen (`72-PDF-TO-MARKDOWN-SPEC.md` section 3).
- **Flags are shown, never written.** A low-confidence OCR word is marked in the preview and listed
  in the report; the file gets the word as read, with no mark (`72-PDF-TO-MARKDOWN-SPEC.md` section 6).
  The drawn page labels such as "page 8, scanned" are preview annotations and say so.
- **From the AI panel, one change.** The conversion lands at the cursor as one queue item and changes
  no byte until it is accepted (`72-PDF-TO-MARKDOWN-SPEC.md` section 4.2).
- **The PDF is not kept.** Tab memory only; dropped when the conversion ends, or when the AI panel
  closes for entry 2 (`72-PDF-TO-MARKDOWN-SPEC.md` section 10).
- **No chat over the PDF.** There is no question box on any frame (`72-PDF-TO-MARKDOWN-SPEC.md`
  section 12).

## Data contract

What | Direction | Port or store | Shape | When
The PDF | held | tab memory only | bytes | From the pick until the conversion ends, or until the panel closes for entry 2
Pages and text | derived | `convertPdf`, the engine of `72-PDF-TO-MARKDOWN-SPEC.md` section 1.2 | markdown and a `ConversionReport` | On pick, page by page
Report | derived | tab memory only | `ConversionReport`, `72-PDF-TO-MARKDOWN-SPEC.md` section 6.2 | With the markdown; never stored, never logged
Entry 1 write | write | `ProjectFiles` with a compare-and-swap on the empty hash | the whole markdown as the first version | On Accept
Entry 2 item | write | the change queue, as S20 reads it | the fields of `72-PDF-TO-MARKDOWN-SPEC.md` section 4.4 | When the conversion finishes, before Accept
Entry 2 accept | write | `ProjectFiles.splice(path, offset, bytes)` | the proposal's bytes at the insertion point | On Accept
Entry 3 write | write | `ProjectFiles.create(folder, name, bytes)` | a new note | On File into Notes
Images, when kept | write | `Uploads.put` | PNG per image | On File into Notes, entry 3 only
Entitlement | read | `limitsFor(account)` | `limits.docs.cloud`, `limits.uploads.*`, the PDF caps of `72-PDF-TO-MARKDOWN-SPEC.md` section 9 | Before the conversion and before the write

**None of this is built.** At `e5fa544` a search of `src` and `src-tauri` for `unpdf`, `pdfjs` and
`tesseract` returned nothing (`72-PDF-TO-MARKDOWN-SPEC.md`, state of the repository), and the same
search of `src` returned nothing again at `9bbcdb4`.

## States

State | When | What is shown | What the person can do
first-run | The first conversion that needs OCR | The OCR files download once; the progress says so | Wait, or cancel.
empty | Nothing picked yet | Entry 1: the start row. Entry 3: the drop area and one line on what it takes | Pick a PDF.
loading | Converting | The progress with pages by kind, and Cancel | Watch, or cancel.
partial | Some pages left out below the page floor | The preview without them, and the report naming them, `72-PDF-TO-MARKDOWN-SPEC.md` section 6.1 | Accept the rest, or discard.
offline | No connection | Text pages still convert; OCR on first use cannot start, `E810` | Convert text PDFs, or use the desktop.
unauthorised | The viewer's role may not write | Entry 1 and 2 are not offered; the tool can file only where the person may write | Read.
over-cap | Too many pages, too large, or too many scanned pages | `E656`, `E657` or `E658`, each with both numbers | Choose a range.
AI-unavailable | The Pro vision pass is out of pages or failing | Tesseract is used and the report says so, `E704` | Carry on.
conflict | The document changed while entry 2 ran | The item still lands; its Accept follows `E027` | Accept against current bytes, or reject.
error | Nothing on any page reached the floor | `E531` | Try a clearer scan.
degraded | Headings or tables guessed, or columns in doubt | Flag lines in the report and marks in the preview | Accept and fix, or discard.

## Responsive

- **Entry 1** shows the starts as full-width rows at thumb height.
- **Entry 2** is the AI panel as a bottom sheet, with the target line shortened to the file and without
  the range link. The flag lines keep only the low-confidence one.
- **The tool is one column**: the file, the preview scrolled to the flagged part, the flag line, the
  folder, one button, and the not-kept note. Discard is under the button, out of the drawing.
- **OCR on a phone is slow.** The scanned-page cap is the same; `UNVERIFIED:` the time per page on a
  phone was not measured.

## Desktop differences

- **Tesseract runs as the native binary**, and there are no caps (`72-PDF-TO-MARKDOWN-SPEC.md` section 9).
- **The new note is written into the chosen folder on disk.** No document cap applies.
- **The PDF stays where the person keeps it.** Nothing is copied.

## What this screen must never do

- **Never keep the PDF**, in R2, IndexedDB, a cache or a log.
- **Never write a flag into the file**, and never correct a low-confidence word silently.
- **Never let entry 2 edit the document directly.** It is one queue item.
- **Never clean the text up with a model in the same step.** That is an AI edit with its own ask.
- **Never offer chat over the PDF**, a summary or "ask this document".
- **Never send a text PDF to a server** to convert it.
- **Never add a third creation button** to the rail for the tool. It is a source on Import and a command.
