# S08. Custom blocks

> Split view, with the bytes on the left and the rendering on the right, so a person can see
> exactly what a block costs them in portability.

> **Ids invented here.** `14-COMPONENT-INVENTORY.md`, `16-COPY-DECK.md`,
> `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md`,
> `55-MEASUREMENT-AND-EVENTS.md` and `56-OPEN-DECISIONS.md` are being written in parallel and did
> not exist when this file was written. Ids follow `65-CONVENTIONS.md` section 3 on a stated
> scheme derived from the screen number: components `C080` to `C089`, errors `E080` to `E089`,
> acceptance `A080` to `A089`. A component owned by another screen is cited by that screen's id.
> Copy ids are namespaced `K.s08.*`, so they cannot collide.

> **Error ids are provisional, and they clash.** `17-ERROR-AND-REFUSAL-CATALOGUE.md` now exists and
> is the home for every error id. It allocates by **category**, not by screen: engine `E001` to
> `E025`, validation `E030` to `E041`, permission `E050` to `E060`, quota `E070` to `E079`, model
> `E080` to `E087`, provider `E090` to `E097`, network `E100` to `E104`, conflict `E110` to `E117`.
> The `E` ids below were allocated from this screen's own block before that register existed, so
> many of them name a different error there. **Read them as descriptions, not as keys**, and
> reconcile each one into its category block. Every row states what the error is, so the mapping is
> mechanical. Component, acceptance and copy ids are unaffected.

## Purpose

Show the five block kinds working side by side with their source, and state in the screen itself
what each one becomes in a tool that has never heard of us.

### The five blocks, and what a stranger's tool shows

This table is the honest part of the screen and it is drawn on the screen itself, not hidden in a
help page.

Block | Carrier | GitHub | Obsidian | A plain parser
Table | GFM table | a table | a table | a table
Chart | a fenced `fm-chart@1` block under the table | a code block, and the table above it is still a table | the same | the same
Mermaid | a fenced `mermaid` block | renders | renders | a code block
Callout | `> [!tip]` | renders as a note | renders | a blockquote with a bracketed word
Maths | `$d = 0.2 \times p$` | renders | renders | the source text, readable
Drawing | a fenced `fm-draw@1` block plus a stored file | a code block and a link | a code block and a link | the same

**The rule behind every row.** The settled position is a callout for prose and a fence for opaque
data. An unclosed fence swallows the rest of the document; a callout has no closer to lose. So
anything that is read as prose takes the callout, and anything that is read by a machine takes the
fence.

### The chart block, in detail

The plan's section 20 gives every invented format four required parts. For `fm-chart` they are:

Part | Value
Version field | the info string carries it, `fm-chart@1`
Unknown fields | ignored, and kept on a round trip
In a plain reader | a code block, with the table above it still a plain table
Test | a fixture per block, with a byte-exact round trip

- **The chart points at the table; the table does not know about the chart.** That is what keeps the
  table a plain table in every other tool.
- The block body is two lines in the drawn example: a kind, and which table to read.
- **The shape is copied from obsidian-charts, the code is not.** That plugin is under the AGPL, and
  the plan records the constraint as a finding. Reading its source to reimplement is a licensing
  risk, so the block is written from the published block shape alone.

## Data contract

What | Direction | Port or store | Shape | When
Open file bytes | in | `DocumentReader.open(path)` | `{bytes, version, headHash}` | on mount
Block parse | in | derived in the client | a block list with byte ranges | on every parse
Chart data | in | read from the table above the block, in the same document | rows and columns | on render
Drawing file | in | `AttachmentReader.get(id)` | the stored drawing | on render of an `fm-draw` block
A block edit | out | `DocumentWriter.splice()` | the block's byte range and its new bytes | on commit
Gutter position | out | account preferences | a percentage | on drag, debounced

- **A chart never stores its own data.** It reads the table above it, so there is one copy of the
  numbers and the table stays editable as a table.
- **Every block reports its own splice range.** The plan's architecture rule is that adding a block
  is a registration and never an edit to the splicer.
- Nothing on this screen calls a model. Blocks are deterministic.

**A block that cannot render shows its source, never an empty space.** `E080` through `E084` all
degrade to the fenced text with the reason beside it, because the bytes are the truth and hiding
them helps nobody.

## Keyboard and focus

- The caret stays in one pane at a time. Clicking a rendered block moves the caret into its source.
- Tab does not move between panes; it inserts a tab, because these are editors.
- The gutter is reachable by keyboard and moves in five per cent steps with the arrow keys.
- The slash menu opens with `/` at the start of an empty line, as it does in every mode.
- No shortcut is registered by this screen, so there is nothing to conflict with the global map in
  `15-INTERACTION-AND-KEYBOARD.md`.

## Responsive

- **Split does not exist at phone width.** There is no room for two panes and a gutter that a thumb
  can hold.
- The phone shows the rendered side, in Reading mode, and the source is reachable by switching to
  Edit.
- The chart scales to the width. The drawn phone example renders the same pie at a smaller size.
- A wide table scrolls sideways inside its own frame rather than making the page scroll.
- Mermaid diagrams scroll sideways in their own frame for the same reason.

## What this screen must never do

- **Never store a chart's data inside the chart block.** It reads the table above it, so there is
  one copy.
- **Never rewrite a table to suit a chart.**
- **Never hide a block that failed to render.** Show the source and the reason.
- **Never drop an unknown field from an `fm-` block.** Ignored and kept, per the plan's section 20.
- **Never omit the version from an `fm-` info string.**
- **Never use a fence as the carrier for prose**, and never use a callout as the carrier for opaque
  data. That is the settled position and this is the screen where it is most tempting to break it.
- **Never copy code from an AGPL-licensed plugin.** The shape is public; the source is not ours to
  take.
- **Never rewrite the whole file to edit one block.**
- **Never render a sandboxed HTML block.** The plan refuses it, because published pages ban
  third-party scripts.
- **Never normalise whitespace on a round trip.**
