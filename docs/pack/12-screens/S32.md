## Purpose

Every provider refused, my document is untouched, my credits are untouched, and here is what I can
do instead.

## Entry and exit

**This screen is never an apology.** It is the state in which the product still offers something,
and the founders' decision of 18 September gave it the thing to offer.

how a person arrives | what was happening
An AI edit on a selection | Every provider in the edit chain refused or timed out
The AI box on a document | The same, on the document chain
Starting a blueprint | The blueprint chain refused, so the standard question set is offered instead
Turning a page in idea mode | A rewrite could not be generated, so the questions already planned stand
The right rail | The AI control is already disabled, with the reason on it

how they leave | what happens
Try again | The chain is re-attempted, skipping any provider with an unexpired stated reset
Use a standard question set | Idea mode continues on the standard set. Nothing waits on a model
Use the local model | Desktop only. The edit runs on the machine and nothing leaves it
Use my own key | Settings, AI, the key field, when that flag is on in S37
Carry on writing | The document was never touched. The editor is behind this box and works

**Why each row's wording differs, which is the hard part of this screen.** `[M]` opened 2026-09-18
by the router research. These are the real dialects, and a row that states the wrong one is worse
than a row that states nothing.

provider | exhausted, meaning stop | transient, meaning try again | what the row can honestly say
Cloudflare Workers AI | 429 with internal code `3036`, the daily free allocation of 10,000 neurons | 429 with internal code `3040`, capacity temporarily exceeded | The reason and a true reset, because its limits reset daily at 00:00 UTC. `docs/research/2026-09-18-llm/raw/L3-router-design.md:594`
Groq | 429, and the remaining-requests header for the day reaching zero | 429 carrying `retry-after` in seconds | The seconds, where the header is present. Never a daily token reset, because no header reports it. `docs/research/2026-09-18-llm/raw/L3-router-design.md:623`
Cerebras | 429 naming which of its two token buckets was exceeded | The same 429 | The bucket, and no reset at all, because its quota refills continuously rather than resetting. `docs/research/2026-09-18-llm/raw/L3-router-design.md:636`
SambaNova | Not established | Not established | A timeout or a refusal, and nothing about pools. See the disagreement below
Every row above declined | | | The one line at the top

**Three build instructions fall out of that table.**

- **The HTTP status alone cannot tell exhaustion from a blip.** Cloudflare returns 429 for both, and
  only the internal code separates them.
  `docs/research/2026-09-18-llm/raw/L3-router-design.md:598` calls that the single most important
  sentence in the document. A row that reads try again in a moment when the daily pool is gone is a
  lie the screen repeats for the rest of the day.
- **No circuit breaker in the survey measures exhaustion**, only failure,
  `docs/research/2026-09-18-llm/raw/L3-router-design.md:579`. A provider whose pool is finished is
  not failing. It is correctly saying it is out, and must not be retried on the failure schedule.
- **A reset time is shown only where the provider states one.** Cloudflare states 00:00 UTC. Cerebras
  has no notion of a reset. Groq reports a per-minute token reset and never the daily one. Inventing
  the missing ones would make this the most confidently wrong surface in the product.

**A disagreement between two sources, named rather than resolved.** The drawn screen and
`docs/mvp0/PRODUCT-PLAN.md` section 14 both put SambaNova in the chain, the plan quoting 20 requests
a day per model from its pages. The free-provider research lists SambaNova among those it never
reached, `docs/research/2026-09-18-llm/raw/L1-free-providers.md:908`. Both can be true, because they
are different sessions opening different pages. Until one is re-opened, this screen states
SambaNova's row from a live response and never from a published limit.

**The streamed failure is the one that will be got wrong.**
`docs/research/2026-09-18-llm/raw/L3-router-design.md:788` states that the error can be the first and
only event in the stream, so a 200 carrying an error chunk with no content is a failure and not a
success. Anything already painted must be discarded rather than left in the document.

## What this screen must never do

- **Never apologise and stop.** `[Z]` the founders' decision of 18 September exists so this screen
  has something to offer. At least one way forward is always shown.
- **Never deduct for a failed call.** The credit note is a promise the ledger has to keep.
- **Never touch the document.** No partial text, no draft of a failed edit, no marker.
- **Never invent a reset time.** Show one only where the provider states one.
- **Never use the same wording for exhausted and transient.** They are different facts, and on two
  of the four providers only an internal code separates them.
- **Never retry an exhausted provider on the failure schedule.** A breaker that treats exhaustion as
  failure retries a finished key every few seconds for the rest of the day.
- **Never blame the person's document.** The chain list exists so they can see it was not their
  file, which is the generator's own stated reason for drawing it.
- **Never show a provider that is not in the chain.** A provider whose terms nobody opened has no row
  here, and no switch on S36 either.
- **Never conflate this with S33.** Our failure and their limit are different screens, with different
  copy and different exits.
- **Never probe a provider to fill in this screen.** The pool state is read from our own ledger. A
  probe call to find out whether a provider is up spends the pool this screen is reporting on.
