## Purpose

Read a long procedural document as a board of phases and steps, without adding one character of
new syntax to the file.

## The one thing that makes this cheap

**Flow view invents no format.** The plan's section 20 lists it with no version field and no unknown
field rule, because its conventions are ordinary headings and lists. A phase is an H2, a step is an
H3, and the tag is a bracketed first word.

That is why the whole screen is a projection and why deferring it costs nothing at the file level.
A document written today already reads correctly in this view whenever it ships.

### The reading rules

These four rules are the whole parser. A document that follows them reads as a flow; one that does
not still reads as a document.

Element | Becomes | If it is missing
An H2 | a phase column | with no H2 at all, `E090`, and the view offers Page instead
An H3 under it | a step card in that column | a phase with no steps renders as an empty column, which is legible and correct
A bracketed first word in the step body | the tag badge on that step | the step renders with no badge
The step's trailing line | the reference line | the step renders with no reference

- **Nothing here is a new syntax.** A bracketed first word is ordinary text, and a trailing line is
  ordinary text.
- The convention is printed on the screen, in `C095`, so a person can make their document read
  better without opening documentation.
- **An H3 before any H2 is a step with no phase.** It is `E091`, and it renders in a leading column
  named for the document rather than being dropped.

### `[X]` Two colour vocabularies, and they do not agree

Reading `docs/mvp0/screens/gen.mjs` at `0af3c90`:

Where | Values
The legend, `C095` | Data, Signal, Portfolio, Prediction, each with a colour
The badges drawn on steps, `C094` | GATE, ALARM, IO, LOOP, HARD, NEW

The legend keys four lanes. The badges carry six different words. Nothing in the generator maps one
set onto the other, so a reader cannot tell what a badge's colour means from the legend beside it.
See D25. This file specifies the parser and leaves the vocabulary open, because inventing a mapping
here would be exactly the guess the product exists to refuse.

## Data contract

What | Direction | Port or store | Shape | When
Open file bytes | in | `DocumentReader.open(path)` | `{bytes, version, headHash}` | on mount
Phase and step tree | in | derived in the client from the bytes | headings with their byte ranges | on every parse
Counts | in | derived from the same tree | two numbers | on every parse
Reference targets | in | `GraphReader.resolve(link)` | a path, or nothing | on render, per reference
Chosen view | out | account preferences, per document | one of six | on change
An edit | out | `DocumentWriter.splice()` | the step's byte range | only from the editor, never from the board

- **The board is read-only.** Dragging a card does not reorder the document, and this file does not
  specify a drag. See D26.
- Nothing is stored about the board. Close it, reopen it, and it is rebuilt from the bytes.
- No model is called. The view is deterministic.

## Keyboard and focus

- **Left and right arrows scroll the board sideways.** That is stated in the legend, because a
  sideways board is not obviously keyboard-reachable.
- Tab moves between step cards in reading order: down a column, then to the next column.
- Enter on a focused step opens its source in Edit mode.
- The view menu opens from the toolbar and closes on Escape.
- No shortcut is registered by this screen. The full map is `15-INTERACTION-AND-KEYBOARD.md`.

## Responsive

- The menu becomes a scrolling chip row, `C098`, with the current view first and selected.
- Fewer columns are in view, and the board still scrolls sideways.
- A phase column takes most of the width, so one phase at a time is readable rather than four being
  unreadable.
- **Kanban and Split are the two views that do not work at phone width.** Flow does, because a
  sideways board and a phone are compatible.

## What this screen must never do

- **Never invent a syntax.** The moment this view needs a marker in the file, it stops being free
  and becomes a format with a version, an unknown-field rule and a fixture.
- **Never write to the document from the board.**
- **Never drop a step it cannot place.** Put it in a leading column and say why.
- **Never show a badge whose colour the legend does not explain.**
- **Never persist board state.** The board is a projection and reopening rebuilds it.
- **Never present a heading structure as wrong.** A document that does not read well as a flow is a
  document, not an error.
- **Never use an emoji as a tag badge.**
- **Never be scheduled into phase A on the strength of this file existing.** The founders deferred
  it.

## Limits of this file

- **Not assessed:** the other five views. Slides, Mind map, Kanban and Outline are named in the
  selector and specified elsewhere.
- **Not assessed:** the drawing budget past which a large document degrades. `E093` names the state
  without naming a number, because there is no measured one.
- **Could not be verified:** that the founders' flow site, which the plan names as the reference,
  uses the same four reading rules. It was not opened in this session. `UNVERIFIED:`
- **What would falsify this file:** a decision that the board is writable, which would make it a
  second editing surface rather than a projection, and would pull the projection law into it.
