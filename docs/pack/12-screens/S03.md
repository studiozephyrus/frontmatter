# S03. Home

> The returning screen. The same five ways to start as S02, with the empty state replaced by a
> recent list and a quiet usage pill.

> **Ids invented here.** `14-COMPONENT-INVENTORY.md`, `16-COPY-DECK.md`,
> `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md`,
> `55-MEASUREMENT-AND-EVENTS.md` and `56-OPEN-DECISIONS.md` are being written in parallel and did
> not exist when this file was written. Ids follow `65-CONVENTIONS.md` section 3 on a stated
> scheme derived from the screen number: components `C030` to `C039`, errors `E030` to `E039`, acceptance `A030` to `A039`. A component owned by another screen
> is cited by that screen's id. Copy ids are namespaced `K.s03.*`, so they cannot collide.

## Purpose

Put a person back where they left off in one tap, and show what they have without making them open
a plan page to find out how much of it is left.

## Entry and exit

Direction | Route or control | Goes to | Notes
Arrive | `/` with one or more documents | this screen | the document count is the only switch away from S02
Arrive | Home in the header, or Home on the phone bar | this screen | from anywhere in the product
Leave, a recent row | tap a row in `C033` | S04, that file, in a new tab | the most recent row is first
Leave, a start card | `C025` | as S02 | the same five, in the same order
Leave, Ideas tab | `C032` tab two | S12 when ideas exist, S34 when none do | the tab carries its count
Leave, Shared tab | `C032` tab three | the shared list | the tab carries its count
Leave, row menu | `C035` on a row | rename, duplicate, export, move to trash | a menu, never an inline destructive control
Leave, usage pill | tap `C031` | S29, plan and usage | the pill is a link, not just a readout
Leave, Search | `C028` or Command K | search overlay across documents, ideas and shared pages | global
Leave, Settings | header icon | S28 | account-level

### The recent row, column by column

Column | What it holds | Sort | Empty case
Recent | The file name, with a `description` icon | the sort key, newest opened first | never empty; a row exists because a document does
Project | The project the file sits in | not sorted | loose files show the project as a dash, never as blank
Opened | Relative for today and yesterday, then a date | follows Recent | a document never opened since creation shows its creation time
Owner | You, or the collaborator's name | not sorted | a shared document always names its owner
Menu | `more_horiz` | n/a | always present

- **Newest opened is first.** The plan's reason is Apple's guidance on restoring the previous state,
  so the first row is the thing a person most likely wants.
- Opened means opened by this person, not last modified by anyone. Two people see two different
  orders for the same project, and that is correct.

### The usage pill

- It reads documents used against the document cap, and nothing else. One number, one cap.
- It is quiet: the same weight as a tab label, never an alert colour, never a progress bar.
- It changes colour only at the cap, and even then it states rather than warns. S33 is where the
  over-cap conversation happens.
- **On Pro it is absent**, because there is no cloud-document cap to show.

## Data contract

What | Direction | Port or store | Shape | When
Recent documents | in | `WorkspaceReader.listRecent(limit)` | rows of `{path, project, openedAt, owner}` | on mount
Document count and cap | in | `EntitlementsReader.forAccount()` plus the count | two numbers | on mount
Idea count | in | `IdeaReader.count()` | `number` | on mount, for the tab
Shared count | in | `ShareReader.countSharedWithMe()` | `number` | on mount, for the tab
Account profile | in | `AuthGateway.observeUser` | `AuthUser` | on mount
Open a document | out | `DocumentReader.open(path)` | bytes plus the head version | on row tap
Row action | out | `DocumentWriter.rename \| duplicate \| trash` | per action | from `C035`
Dropped files | out | `ImportService.beginImport()` | handle list | on drop anywhere

- The shipped app has `VaultReader` at `src/modules/vault/application/ports.ts` with `getHeadSha`,
  `getZipball`, `getFile`, `listHistory` and `getFileAtSha`. It reads a GitHub repository, not the
  workspace this screen describes. Everything above is `specified, not built`.
- **The counts are three separate reads and must not block each other.** A slow idea count leaves the
  Ideas tab without its number while the rest of the screen works.
- Nothing on this screen reads document bytes. The recent list is metadata only, so a large vault
  does not make home slow.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Open a document | tap a row | opens S04 with that file in a new tab | not found `E031`; no permission `E032` | `doc.opened`
Open the row menu | tap `C035` | a menu beside the row | none | `home.rowmenu.opened`
Rename | row menu | inline rename on the row, committed on Enter | name taken, so the rename is refused and the old name stands | `doc.renamed`
Duplicate | row menu | a copy beside the original | over the document cap `E034` | `doc.duplicated`
Export | row menu | a single-file export | export failed `E038` | `doc.exported`
Move to trash | row menu | a 30-day trash, never a delete | write failed `E033` | `doc.trashed`
Switch tab | tap `C032` | Documents, Ideas or Shared | none | `home.tab.changed`
Open plan and usage | tap `C031` | S29 | `E030` | `plan.opened`
Choose a start | `C025` | as S02 | as S02 | `home.start.chosen`
Drop a folder | drop on `C020` | begins an import | `E036`, `E035` | `tree.drop.received`
Search | `C028` or Command K | the overlay, across all three tabs | index unavailable `E039` | `search.opened`

**Move to trash is the only destructive row action and it is never a delete.** The plan's data model
gives a document 30 days in trash before it goes.

## States

State | When | What is shown | What the person can do
first-run | not reachable | n/a, zero documents routes to S02 | n/a
empty | a tab with no rows | that tab's own empty line, inside the table frame | switch tab, or start
loading | the recent read is in flight | header, tabs and grid, with skeleton rows | start a document
partial | rows arrived, a count did not | the tab without its number | everything works; the number appears when it lands
offline | no network | the last list from the device cache, marked as such | open a cached document, or start one
unauthorised | the session expired | routes to S01 | sign in again
over-cap | at or past the document cap | the pill states it, and the start cards that create a document say so | export or trash something, or open S29
AI-unavailable | the chain is down | card two says the depth is unavailable | the other four work
conflict | a listed document has an unresolved conflict | the row carries a conflict marker | open it, which lands on S31
error | the recent read failed | the table area carries `E037` with a retry | retry, or start a new document
degraded | counts unavailable, list fine | tabs without numbers, no usage pill | everything else works

## Keyboard and focus

- On arrival focus is on the first recent row, because the most likely next action is to reopen it.
- Up and down move through the rows. Enter opens the focused row.
- The five start cards are one composite stop above the list, reached by shift-tab from the first
  row.
- Command K opens search. Command Enter on a focused row opens it in a background tab.
- The row menu opens on the menu key or on Shift F10, as well as on tap.
- No conflict with the global map in `15-INTERACTION-AND-KEYBOARD.md`.

## Responsive

- The recent table loses the Project and Owner columns on the phone. Both fold into a subline under
  the file name, joined by a middle dot.
- The tabs shorten: Shared with me becomes Shared, and the counts stay.
- The phone shows four start cards, as S02 does.
- The usage pill moves below the greeting on the phone rather than beside it.
- The bottom bar carries Home, Search, AI, Outline and More, with Home lit.

## Desktop differences

- The desktop build adds a second group above Recent for folders on this machine, because the plan
  gives the desktop app a tree that mixes cloud projects with local folders.
- **The usage pill is absent on the desktop build.** The plan makes the desktop app free of the
  document cap, so showing a cap there would be wrong.

## What this screen must never do

- **Never show a tour, a coach mark or a what-is-new modal.** The standing founders' rule.
- **Never delete a document from a row.** Trash, with 30 days, and nothing faster.
- **Never turn the usage pill into an upsell.** It states a number and links to S29.
- **Never sort the recent list by modified time** and call it Opened. The column name is the truth.
- **Never read document bytes to render the list.**
- **Never block the whole screen on any one of the three counts.**
- **Never show a cap on the desktop build.**
- **Never put a start card and a recent row in the same grid.** They are different kinds of thing and
  mixing them makes both harder to scan.

## Limits of this file

- **Not assessed:** the search overlay. It is named as an exit and specified in its own screen.
- **Could not be verified:** that a shared document always carries an owner name in the record. The
  plan's permissions table implies it. `UNVERIFIED:` against the data model as built.
- **What would falsify this file:** a decision to make Opened mean last modified, or a decision to
  give the desktop build a cap, either of which would invert two rules above.
