## Purpose

Hand the finished kit over: read the fifteen files, check they agree, copy the link and the prompt
that makes an agent build from them.

## Data contract

what | direction | port or store | shape | when
Kit manifest | read | `KitStore.manifest(kitId)` | `{ version, files: [{ path, bytes, sha256 }], rootHash, createdAt }` | On arrival
File body | read | `ProjectFiles.read(path)` | The bytes, unchanged | When a row is opened
Consistency result | read | `KitChecker.result(kitId)` | `{ compared, fixed: [{ path, from, to }], remaining }` | With the manifest
Unlisted link | read | `KitStore.link(kitId)` | `{ url, revoked, indexed: false }` | On arrival
Root hash | read | `KitStore.manifest(kitId).rootHash` | A sha256 over the tarball, printed on the page | On arrival
Kickoff prompt | read | `KitStore.kickoff(kitId, target)` | Text, with the link and the hash already in it | When a target is chosen
New version | write | `KitStore.publish(ideaId)` | A new manifest, a new tarball, a raised version | On publish
Revocation | write | `KitStore.revoke(kitId)` | `{ revoked: true, at }` | On revoke
Entitlement | read | `limitsFor(account)` | `limits.ai.blueprints` | Before a publish
Ledger | write | `UsageLedger.record` | `{ account, kind, delta, model, cost }` | On a publish that calls a model

**Every port above is specified, not built.** At `0af3c90` there is no `src/modules/ideas/` and no kit
store. The tarball, the manifest and the checksum file are named in the plan at
`docs/mvp0/PRODUCT-PLAN.md` section 5 and exist nowhere in `src/`.

**The hash on the page is the whole point.** A checksum file inside the tarball proves the transfer
was intact. Only a hash carried outside the tarball proves the kit is the one we published. That is
the plan's own reasoning at `docs/mvp0/PRODUCT-PLAN.md` section 5.

## Actions

action | trigger | what happens | failure behaviour | event id
Open a kit file | Click a row in the file list | The file opens in the document pane, byte for byte | File missing from the manifest, so `E307` names the path | `kit.file.opened`
Copy the link | The copy control on the link row | The unlisted URL goes to the clipboard | Clipboard refused by the browser, so `E308` shows the string to select | `kit.link.copied`
Copy the hash | The copy control on the hash row | The root hash goes to the clipboard | as above | `kit.hash.copied`
Choose a target | The three-way segment | The prompt is rewritten for that agent, with the same link and hash | Unknown target, so `E309` falls back to the first | `kit.kickoff.retargeted`
Copy the prompt | The full-width copy control | The whole prompt goes to the clipboard | as above | `kit.kickoff.copied`
Open the map | The map row, or the view selector | S16 opens on the same kit | Graph not rebuilt, so `E310` rebuilds and says so | `kit.map.opened`
Edit and publish | The rail foot control | The next version is minted, the old one stays fetchable, the hash changes | Over the cap, so `E072` sends to S33 | `kit.version.published`
Revoke the link | Revoke, from the link note | The link stops resolving. The files stay | Already revoked, so nothing happens | `kit.link.revoked`
Download the tarball | The link, followed by an agent or a person | The tarball is served with its content hash in the response | Revoked, so `E311` returns a plain refusal and not a redirect | `kit.tarball.fetched`

**`E311` returns a refusal, never a redirect to sign-in.** A revoked kit link is a dead link, and a
dead link that bounces an agent into a login page is the failure S18 exists to prevent.

## States

state | when | what is shown | what the person can do
first-run | The first blueprint on this account | One line explaining what a skill folder is | Read it, or carry on.
empty | No blueprint has been written for this idea | The screen is not reachable; the ideas rail sends to S13 | Answer the questions.
loading | The kit is being written | The file list fills row by row as each file lands | Wait. The link and the hash appear only when every file is in.
partial | Some files written, the run interrupted | The rows written are ticked, the rest are pending, no link and no hash | Resume, or discard.
offline | No connection | The kit is readable from the local copy. Copy controls work. Publish is disabled with its reason | Read, copy, come back to publish.
unauthorised | The link opened by somebody who is not the owner | The kit reads, because the link is the permission. Publish and revoke are absent | Read and download.
over-cap | Blueprint credits spent | The existing kit stays. `E072` covers a new version | Top up, wait for the reset, or go to Pro.
AI-unavailable | Every provider refused during a publish | The last good version stays intact and current. Nothing charged | Retry, or use the desktop local model.
conflict | A kit file changed on disk under an open kit | S31, both versions kept, nothing merged | Keep one, keep both, or send a proposed merge to the queue.
error | The consistency check itself failed | The kit is shown with the check marked as not run, never as passed | Rerun the check, or publish without it and be told so.
degraded | The check ran and left findings it could not fix | The remaining count is named, with each finding's file | Fix them, or publish with them named.

**A check that did not run is never drawn as a check that passed.** The files-agree pill has three
states and not two: agreed, findings remaining, and not run.

**Focus on arrival is the copy-the-prompt control.** It is the one thing the screen exists to hand
over, and a person who arrives by keyboard should reach it with no travel.

**The prompt block is selectable text, not an image.** A person who cannot use the copy control can
select it, and a screen reader can read it.

## Responsive

- **The kit rail becomes the whole body** at phone width, with the document pane reachable from the
  tree drawer.
- **The prompt block scrolls sideways** rather than wrapping, because a wrapped shell command copies
  wrongly often enough to matter.
- **The copy controls stay full width** at thumb height.
- **Nothing is unavailable at phone width.** A person can read the kit, copy the link, copy the hash
  and copy the prompt from a phone.

## Desktop differences

- **The kit can be written to a folder on disk** as well as to the cloud project, because the desktop
  build has the file system. The rail gains one control for it.
- **The tarball can be verified locally** by the app after a download, so the person sees the same
  check an agent would run.
- Everything else is identical.

## What this screen must never do

- **Never show a link or a hash for a kit that is not complete.** A partial kit has neither.
- **Never draw a check that did not run as a check that passed.**
- **Never redirect a kit fetch to sign-in.** The link is the permission, and an agent cannot answer a
  login page.
- **Never change a published version in place.** A new version is a new hash.
- **Never index a kit page.** It is unlisted by design.
- **Never normalise the bytes of a kit file** when showing it. The file on disk is the truth.
- **Never claim the consistency check makes the agent better.** It says what it compared and what it
  fixed, and nothing about outcomes.
- **Never charge a blueprint credit for a publish that failed.**
