# What I verified myself, 2026-09-09

Not agent output. Each line below was opened by me in this session, from the URL given.
This exists because a research agent attributed quotes to a page that does not contain
them, and the same report's GitHub evidence turned out to be genuine. Both halves matter.

## VS Code — the capability is real, the framing was wrong

**Verified real, via api.github.com (opened directly):**

| Item | Title | Milestone | Dates |
|---|---|---|---|
| PR #324218 | "Agents - add review/unreview operation to the multi-file diff editor" | 1.128.0 | created + closed 2026-07-03 |
| #326539 | "Test: Markdown editor feedback in the Agents window" | 1.130.0 | 2026-07-19 → 2026-07-20 |
| #326540 | "Test: View and edit Markdown in the Agents window" | 1.130.0 | 2026-07-19 → 2026-07-20 |

Body of #326539, quoted from the API response: "The Markdown editor supports feedback
comments on Markdown files created or changed by an agent." It names the gating setting
`workbench.editor.markdownDefaultEditorInAgentsWindow`.
Body of #326540: "The Agents window uses an experimental hybrid editor for viewing and
editing Markdown."

**Refuted:** the claim that <https://code.visualstudio.com/docs/copilot/chat/review-code-edits>
says "The reviewed state clears if you or the agent changes the file again" and "Markdown
files follow the same feedback flow."

That URL now redirects to `/docs/agents/run/review-code-edits`. I read the whole live page
(9,516 characters, footer dated 9/2/2026). It contains **zero** occurrences of: "as
reviewed", "reviewed state", "clears if", "markdown", "locked mode", "attribution".

What the page actually documents as the review flow: the diff view, Source Control,
checkpoints (`chat.checkpoints.enabled`), request editing, worktree isolation, and
sensitive-file approval (`chat.tools.edits.autoApprove`). It says plainly: "Review the
changes as you would other workspace or branch changes."

**The honest statement.** Microsoft has built review/unreview and markdown agent-feedback
into VS Code, shipped in milestones 1.128 and 1.130 (July 2026). It is labelled
experimental, is gated behind a setting, lives only in the Agents window, and is **not
described in the public review documentation**. That is a serious competitive signal and a
clear statement of intent. It is **not** "free, default-on, and in the hands of tens of
millions", which is how the research report framed it.

## Cursor — hole closed, and it goes our way

The research agent could not reach Cursor (Cloudflare challenge) and flagged it as the
biggest hole in the report. I opened it.

- `cursor.com/review` redirects to a sign-in wall. Not opened — signing in is out of bounds.
- `cursor.com/learn/reviewing-testing` opened fine. 11,414 characters read.

Cursor's review offering, from its own words on that page:
- **Agent Review** — "click Review then Find Issues to run a dedicated code review. The
  agent analyzes proposed edits line by line and flags potential problems."
- For all local changes: "open the Source Control tab and run Agent Review to compare
  against your main branch."
- **Bugbot** reviews pull requests on push, with autofix.
- `@Branch` gives the agent the full diff of the current branch.

Searched that page for: "mark as reviewed", "viewed", "markdown", "attribution",
"per-span", "range-based", "unreviewed". **All zero.**

**The finding.** Cursor's answer to too much agent output is *another agent reviews it*.
It is not a human-facing record of what a person has read. That is a different product,
and it leaves the ledger idea unoccupied by the most-cited comparison in the space.

## Calibration on the research agents — trust the substance, not the quotation marks

I spot-checked five quotes by fetching the cited page and grepping for the exact string.

| Cited quote | Source | Result |
|---|---|---|
| "diff panel that opens beside the conversation" | Claude Code CHANGELOG | **found verbatim**, and `2.1.260` is in the file |
| "comments attach to snapshots" | zed.dev/blog/introducing-delta | **found verbatim** |
| "Agent Edits" / "Uncommitted" toggle | antigravity.google/blog/vcs-and-terminal | **found**, both strings |
| "Every edit and conversation is captured between your commits" | zed.dev/blog/introducing-delta | **not on the page** — paraphrase in quotation marks |
| "When the side panel only tracks agent tool edits, your UI gets out of sync…" | antigravity.google/blog/vcs-and-terminal | **not on the page** — paraphrase in quotation marks |
| "The reviewed state clears if you or the agent changes the file again" | VS Code review docs | **not on the page, and the capability is not documented there either** |

**The pattern.** The *capabilities* these agents report are real and check out — Zed Delta
exists, Antigravity's three-way VCS toggle exists, Claude Code 2.1.260 shipped a diff panel,
VS Code merged a review/unreview operation. Roughly a third of the *quotations* are
paraphrases wearing quotation marks.

**How to use this.** Take the findings. Do not put any of these quotes on a slide, in the
plan, or in a decision card without re-fetching the page and matching the string. The one
case where substance itself was wrong (VS Code's public docs) was caught only by opening
the page, so opening the page stays the rule, not the exception.

Two of these — Zed Delta and Almanac — are load-bearing enough that the plan changes either
way, so the correction does not rescue anything. It only changes what we are allowed to
print.
