# S02. Home, first time

> The first screen behind the door, on an account with nothing in it. It is S03 with the recent
> list replaced by an empty state that does three jobs.

> **Ids invented here.** `14-COMPONENT-INVENTORY.md`, `16-COPY-DECK.md`,
> `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md`,
> `55-MEASUREMENT-AND-EVENTS.md` and `56-OPEN-DECISIONS.md` are being written in parallel and did
> not exist when this file was written. Ids follow `65-CONVENTIONS.md` section 3 on a stated
> scheme derived from the screen number: components `C020` to `C029`, errors `E020` to `E029`, acceptance `A020` to `A029`. A component owned by another screen
> is cited by that screen's id. Copy ids are namespaced `K.s02.*`, so they cannot collide.

## Purpose

Give a person with no documents five ways to start, tell them the free caps once, and say plainly
that a folder can be dropped anywhere on the page.

### The five ways to start, in order

The order is fixed. Hick's law is the reason the plan gives for five rather than more, and for one
of them being highlighted.

Position | Card | Icon | What it does
1 | Blank document | `note_add` | a new markdown file, saved as you type
2 | From an idea | `lightbulb` | the accented card; describe it, answer questions, get a brief and a blueprint
3 | Import | `upload` | drop files or a whole folder
4 | From GitHub | `code` | open a repository's docs and write back to them
5 | A template | `table_view` | spec, meeting notes, decision record, README, and more

**Card two is the only accented one.** Two accents would be no accent.

### The empty state carries the words

Founders' proposal 8.1 of 18 September asked that upload be obvious, and placed the words in the
empty states rather than in a third button. So this screen and S34 are where a person is told, in
plain words, that a folder can be dropped.

- It says drop a folder, not drag and drop, and not a file-picker verb.
- It says it inside the recent table's frame, where the eye is already looking for rows.
- It names the free caps **once**, on this screen, and nowhere else in the first run.

## Data contract

What | Direction | Port or store | Shape | When
Document count | in | `WorkspaceReader.countDocuments()` | `number` | on mount; zero selects this screen
Account profile | in | `AuthGateway.observeUser` | `AuthUser` | on mount, for the greeting and the avatar
Plan and caps | in | `EntitlementsReader.forAccount()` | the limit set the panel writes | on mount
Template list | in | `TemplateReader.list()` | template descriptors | when card five is tapped
Dropped files | out | `ImportService.beginImport()` | a file or directory handle list | on drop
New blank document | out | `DocumentWriter.create()` | path plus empty bytes | on card one
Theme | in | account settings, device fallback | `light \| dark \| system` | before first paint

- **None of these ports is built.** The shipped app reads a GitHub-backed vault through
  `VaultReader` at `src/modules/vault/application/ports.ts`. The R2 and record-store ports this
  screen needs are `specified, not built`.
- Caps come from the entitlements record, never from a constant in the source. The plan's
  configuration panel is the only writer.
- The greeting needs a display name and nothing else. It never reads a document.

## States

State | When | What is shown | What the person can do
first-run | zero documents owned | this whole screen | start, drop, or look around
empty | the same condition | `C027` in place of the rows | the empty state is the screen
loading | counting documents | the header, the tabs and the grid, with the table area reserved | start a document; the count is not needed for that
partial | the count arrived, entitlements did not | everything except the caps line | start; the caps line appears when it lands, and never guesses
offline | no network | the full screen, with the drop target live | drop a folder; it queues and uploads on reconnect
unauthorised | session expired mid-view | routes to S01 | sign in again
over-cap | not reachable here | n/a, an account with zero documents is under every cap | n/a
AI-unavailable | the model chain is down | card two stays and says the depth is unavailable, rather than vanishing | the other four still work
conflict | n/a | n/a, nothing is open to conflict | n/a
error | the count call failed | the grid, and the table area carries `E027` with a retry | start anyway, or retry
degraded | entitlements unavailable | the empty line without the caps sentence | start; nothing else changes

## Keyboard and focus

- On arrival focus is on the first start card, so Enter starts a blank document.
- Arrow keys move across the five cards as one composite widget, not five tab stops.
- Tab order: the card grid as one stop, then the tabs, then search, then the header icons.
- Command K opens search from anywhere on this screen.
- No conflict with the global map in `15-INTERACTION-AND-KEYBOARD.md`, because this screen registers
  only Command K, which is global anyway.

## Responsive

- The five cards become a two-column grid at tablet width and one column on the phone.
- **The phone shows four cards, not five.** The template card is the one dropped, and it stays
  reachable from the Documents tab's own menu.
- The tab labels shorten: Shared with me becomes Shared.
- The recent table head is dropped on the phone; the empty line stands alone.
- The bottom bar carries Home, Search, AI, Outline and More, with Home lit.
- **Drop still works on the phone** where the browser supports it, and the words stay either way.

## Desktop differences

- The desktop build adds a line to the empty state saying documents on this machine have no cap.
  The plan makes no-cap a desktop property, so the first-run screen is where it is worth saying.
- Dropping a folder from Finder imports in place rather than uploading, because the desktop app
  holds files on disk.

## What this screen must never do

- **Never show a tour, a coach mark, a product walkthrough or a dismissible tips carousel.** The
  standing founders' rule covers the first run most of all, because the first run is where a tour is
  usually added.
- **Never require a step before the five cards are usable.** No workspace naming, no team invite, no
  role question, no survey.
- **Never hard-code a cap number into a copy string.**
- **Never state the caps more than once in the first run.**
- **Never hide the drop words behind a hover, a menu or an empty-area affordance.**
- **Never use an emoji as the icon on a start card.** All five are Material Symbols as inline SVG.
- **Never block the grid on the document count.** A person can start before the count returns.
