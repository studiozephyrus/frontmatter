## Purpose

Keep writing with no connection, and know exactly what has not reached the server yet.

## Entry and exit

Direction | How | Route or control
In | The connection dropping, anywhere in the workspace | No route change. The banner appears in place
In | Opening the app with no connection, from a previously visited origin | The workspace, from the local copy
Out | The connection returning, which syncs and removes the banner | No route change
Out | The desktop card's download control | S25
Out | Remind me later on that card, which hides it for this account | No route change
Out | A queued change that cannot be placed on reconnection | S31

**This is a state of the workspace, not a screen of its own.** The editor keeps working. Everything
that changes is a banner, one disabled control and one card.

## Data contract

What | Direction | Port or store | Shape | When
Draft body | write | `draftStore` in `src/modules/drafts/infrastructure/draft-store.ts` | `Draft` of `{ content, baseSha, updatedAt }`, keyed by path | On every keystroke, debounced
Dirty index | read and write | `localStorage`, under a key the shipped code already owns | A list of paths with unsynced work | On every change, read synchronously
Last sync | read | The same store | A timestamp | For the banner
Connection state | read | The browser's own online state, plus a failed write | Online or not | Continuously
Sync on return | write | `ProjectFiles.splice`, per queued change | One splice, one version, per change | On reconnection
Persistence grant | write | The browser's storage manager | Granted or not | Requested inside a user gesture, never on load

**Part of this is built.** `src/modules/drafts/` ships a draft store today. It writes to an IndexedDB
store through `idb-keyval` and keeps a dirty index in `localStorage` for synchronous lookups, and its
`Draft` type carries the base hash the splice will need. **The banner, the queue, the sync on return
and the desktop card are specified, not built.**

**Two persistence keys keep a legacy prefix on purpose.** The IndexedDB store name, its object store
and the dirty key are named in `AGENTS.md` section 8 as keys that must not be renamed, because
renaming one silently orphans a person's local drafts.

**What each browser gives, and what Safari takes back** `[M]`, from the plan at section 12.

Browser | Allowance | Line
Chrome | About 60 per cent of the disk, per origin | `docs/mvp0/PRODUCT-PLAN.md` section 12, at line 1071
Firefox | The smaller of 10 per cent or 10 GiB | section 12, at line 1072
Safari | About 60 per cent since macOS 14 and iOS 17, **but it deletes all script-writable storage after seven days of Safari use without a visit**, unless the app is on the home screen | section 12, at line 1073

**The one rule: never let the browser be the only copy**, at `docs/mvp0/PRODUCT-PLAN.md` section 12,
at line 1077. Persistence is requested inside a user gesture, and the first connection pushes
everything to the server. Safari's eviction is the reason the banner is honest and the reason the
desktop card is on this screen rather than somewhere quieter.

**Background sync and the share target exist only in Chromium**, at `docs/mvp0/PRODUCT-PLAN.md`
section 12, at line 1075. So sync on return is driven by the page, not by a background task, on every
other browser.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Go offline | The connection dropping, or a write failing | The banner appears, the tree foot counts, the AI control dims with its reason | none | `offline.entered`
Type | Any keystroke | The draft is written locally, keyed by path, with its base hash | Storage refused or full, so `E107`, which is the one case on this screen that must interrupt | `offline.draft.saved`
Try an AI edit | The dimmed control | Nothing is sent and nothing is charged. The reason is already on screen | none | `offline.ai.refused`
Come back online | The connection returning | Queued changes are spliced in order, the banner goes, the count clears | A change cannot be placed, so S31 | `offline.sync.completed`
Request persistence | The first save in a session, inside the person's own gesture | The browser is asked to keep this origin's storage | Refused, so `E104`, which names the risk in one line and does not nag | `offline.persist.requested`
Download the desktop app | The card's control | S25 | none | `offline.desktop.opened`
Dismiss the card | Remind me later | It is hidden for this account, and not for this session only | none | `offline.desktop.dismissed`
Reach the storage ceiling | The browser's quota | `E107`. New keystrokes still render, and the person is told plainly that they are not being kept | none | `offline.storage.full`

**`E107` is the one interruption allowed here.** Everything else about being offline is a banner. A
keystroke that is not being kept is a different class of problem, and it must say so at once.

## States

State | When | What is shown | What the person can do
first-run | The first time this account goes offline | The banner, and one line saying work is kept on this device | Keep writing.
empty | No unsynced work, and no connection | The banner, with no waiting count | Read, write.
loading | The connection state is being established | Nothing. The banner waits until the state is known, so it never flickers | Carry on.
partial | Some changes synced, some still queued | The count falls as each lands | Watch, or carry on writing.
offline | This screen. No connection | The banner, the count, the dimmed AI control, the desktop card | Everything except AI and sharing.
unauthorised | The session expired while offline | Local drafts stay readable and exportable. Nothing syncs until sign-in | Export, or sign in when back.
over-cap | The account is over a cap and offline | Local editing continues. The cap is enforced on sync, not on the device | Write, then resolve on S33.
AI-unavailable | Always, in this state, on the web | The dimmed control and its reason | Use the desktop local model.
conflict | A queued change cannot be placed on reconnection | S31. Both versions kept, nothing merged | Keep one, keep both, or propose a merge.
error | A local write failed | `E107`, at once, because the keystroke is not being kept | Free space, or use the desktop app.
degraded | Storage is granted but nearly full | A quiet line in the banner naming how little is left | Free space, sync, or install.

## Keyboard and focus

key | does
Everything the editor does | Unchanged. Going offline takes no shortcut away
Escape | Dismisses the desktop card

**Focus never moves when the connection drops.** A person typing mid-sentence keeps the caret they
had. A banner that steals focus loses a keystroke, and losing a keystroke is exactly what this screen
exists to prevent.

**The banner is announced once, politely**, in a live region. The storage-full case is the exception
and is announced assertively, because it changes whether typing is being kept.

**UNVERIFIED:** `15-INTERACTION-AND-KEYBOARD.md` lists no binding for this state, so nothing above
collides.

## Responsive

- **The banner takes the shorter wording** and sits above the toolbar, as drawn at `docs/mvp0/screens/gen.mjs:1464`.
- **The desktop card is absent on the phone.** Offering a Mac download on a phone is noise.
- **The last sync time moves into the banner**, since there is no tree foot on screen.
- **Nothing is unavailable at phone width** beyond what is unavailable on the desktop web.

## Desktop differences

- **The local model takes over.** AI edits keep working with nothing leaving the machine, which is why
  the dimmed control's reason names it.
- **There is no storage ceiling to hit.** Files are on disk, so `E107` cannot fire.
- **Safari's eviction does not apply**, and neither does the persistence request.
- **The desktop card is absent**, because the person is already there.

## What this screen must never do

- **Never let the browser be the only copy.**
- **Never move focus** when the connection drops or returns.
- **Never hide the AI control.** Dim it, and put the reason under it.
- **Never charge for an attempt** that never reached a provider.
- **Never merge a queued change silently** on reconnection.
- **Never rename the local storage keys** without a migration. Renaming one orphans a person's drafts.
- **Never promise the browser will keep the data.** Safari evicts after seven days without a visit,
  and the copy says so rather than implying durability.
- **Never nag.** The persistence request is asked once, and the desktop card is dismissed for good.
