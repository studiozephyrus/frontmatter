# S04. Workspace

> The screen a person is in most of the day. It carries the heaviest set of founders' instructions
> in the 18 September review, and every one of them is a placement rule.

> **Where the ids come from.** Every `C`, `E`, `A` and `K` id below lives in its register:
> `14-COMPONENT-INVENTORY.md`, `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md` and
> `16-COPY-DECK.md`. The ids this screen first proposed were reconciled into those registers on 18
> September 2026. The old-to-new mapping is in `tools/error-map.json`, `tools/component-map.json`
> and `tools/acceptance-map.json`, and `tools/validate-pack.py` fails if any id here has no home.

folded away until it is wanted.

### The left rail, in the order it reads

The review moved Add file here from the bottom right and added Add idea beside it. Proposal 8.1
then refused a third button and put upload inside the first one. That refusal is the design.

Position | Element | Why it is there
1 | Tree head, with the add-project pill | projects are the coarse unit, so their control sits above them
2 | Project groups, with their file rows | the content
3 | **Ideas, collapsed, with a count** | the review's own comparison is the outline on the right: present, shut, one tap away
4 | Drop hint | the words that make upload discoverable without a button
5 | **Add file**, primary, with a chevron | opens a menu, never creates on the first click
6 | **Add idea**, secondary | routes to S12
7 | Sync foot | state, not an action

- **Two buttons. Not three.** A third upload button would compete with the two the founders named.
- **The chevron on Add file is load-bearing.** It says a menu follows, so a person does not tap it
  expecting an immediate blank file.
- **Notes stays expanded, Ideas stays collapsed.** That pairing is the 18 September decision.

## Data contract

What | Direction | Port or store | Shape | When
Tree | in | `WorkspaceReader.tree(projectId)` | nested project and file nodes | on mount, and on any tree write
Idea count | in | `IdeaReader.count()` | `number` | on mount, for `C104`
Open file bytes | in | `DocumentReader.open(path)` | `{bytes, version, headHash}` | on tab activation
Outline | in | derived in the client from the open bytes | heading nodes with byte offsets | on every parse
Backlinks, tags, comments | in | `GraphReader`, `CommentReader` | counts, then the lists on open | counts on mount, lists on expand
History window | in | `EntitlementsReader.forAccount()` | a day count | on mount
Credits | in | `LedgerReader.balance()` | used against the cap | on mount, and after every AI call
A keystroke | out | local draft store first, then `DocumentWriter.splice()` | a byte range and its replacement | debounced
Sync state | in | `SyncStatus.observe()` | last sync time, queue depth | continuous
Dropped files | out | `ImportService.beginImport()` | handle list | on drop

- **Every write is a splice.** The engine locates a byte range and replaces exactly those bytes. It
  never rewrites the whole file, and it refuses rather than guess when a range is ambiguous.
- **The local draft is written before the server.** The plan's rule is that the browser is never the
  only copy, and the first connection pushes everything.
- The outline is a projection of the open bytes and is never stored. Reopening a file rebuilds it.
- Counts are read on mount; the lists behind them are read only when a row is expanded. A closed
  collapsible costs nothing.

## States

State | When | What is shown | What the person can do
first-run | the very first document, from S02 | the full workspace with one empty tab | write; the AI box is offered once
empty | the open file has no bytes | the document surface with a muted placeholder heading | write, or open AI
loading | bytes in flight | the chrome, the tree and a reserved document area | switch tab, use the tree
partial | bytes arrived, counts did not | collapsibles without numbers | everything works
offline | no network | a banner, the last sync time, the queue depth | write; every keystroke lands locally
unauthorised | the session expired | routes to S01, with drafts kept locally | sign in; nothing is lost
over-cap | at the document cap | Add file's create item is disabled and says why | export or trash, or open S29
AI-unavailable | the chain has refused or timed out | the AI edit button is dimmed with a one-line reason | write; on the desktop the local model takes over
conflict | two versions of the open file exist | a marker on the tab, and S31 on opening it | resolve on S31; nothing is merged here
error | a splice was refused | the change is not applied, and the reason names the range | edit the range so it is unambiguous
degraded | the outline parser failed | the outline panel says so; the document is untouched | keep writing

**A refused splice is a correct outcome.** The document is left exactly as it was, which is the
whole differentiation. It is never a silent no-op and never a best guess.

## Keyboard and focus

- On arrival focus is in the document, at the position last held for that file.
- The twelve tools carry the usual marks: Command B, I, K for link, and Command Shift for the block
  tools. The full map is `15-INTERACTION-AND-KEYBOARD.md`.
- Command P opens the tree's file search. Command Shift H goes home.
- Escape from any open rail panel returns focus to the document.
- The tab strip is one composite stop; left and right move between tabs.
- **There is no Shortcuts panel and no Shortcuts row anywhere**, so the map lives in S28 only.
- The tree is a single tree-view widget with arrow-key navigation, not one tab stop per row.

## Responsive

- **The tree and the right rail become drawers** over a backdrop, at 280 px and 300 px.
- **The toolbar keeps seven tools**: bold, italic, bulleted list, checklist, link, image, overflow.
- **The mode segment moves into the header** and shortens to Edit, Live, Read.
- The bottom bar carries Home, Search, AI, Outline and More. None is lit inside a document, because
  a document is not one of the five destinations.
- Add file and Add idea live at the foot of the tree drawer, in the same order.
- Split mode is not available at phone width. Live is the default.

## Desktop differences

- The tree mixes cloud projects with folders on this machine, under two headings.
- A watched folder feeds an agent's on-disk edits into the change queue.
- No document cap, so the Add file menu never disables its create item.
- The AI edit button can fall back to a local model when the network chain is unavailable.

## What this screen must never do

- **Never show a Shortcuts button, row, panel or hint.** The instruction was to remove it everywhere,
  and everywhere includes a tooltip.
- **Never put a third creation button in the left rail.**
- **Never put upload anywhere except inside Add file**, with the tree as a silent second route.
- **Never open Ideas expanded by default.**
- **Never put a collapsible below the outline.**
- **Never show the wordmark in the workspace.** It belongs to the front door and the published page.
- **Never give Share a visible text label.**
- **Never route away to open the AI box.** It opens over the workspace, as Notion's does.
- **Never write to the file without the person accepting**, for anything an AI or an agent proposes.
  Those go to the change queue.
- **Never guess a byte range.** An ambiguous range is refused, and the document is left unchanged.
- **Never rewrite a whole file to apply a toolbar mark.**
- **Never let the browser be the only copy of a keystroke.**
- **Never use an emoji for any control here.** All of them are Material Symbols as inline SVG.
