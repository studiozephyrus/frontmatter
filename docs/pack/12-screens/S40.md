# S40. Board

> **Where the ids come from.** Every `C`, `E`, `A` and `K` id below already lives in its register:
> `14-COMPONENT-INVENTORY.md`, `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md` and
> `16-COPY-DECK.md`. An id written `new:` plus a slug is a proposal. None of them is in a register
> yet, and "Register rows needed" at the foot lists every one for its owner.

> **What this screen draws.** The files, the writes and the refusals belong to
> `69-BOARDS-SPEC.md`. This file says only how a person meets them. Where the two disagree,
> `69` wins and this file is the one to fix.

## Purpose

See where every task stands, move a card when its work moves, and see what an agent wants to move
before it happens.

## The rules this screen carries

- **One card is one markdown file; the columns come from its `status` key.** The board file names
  the folder, the key, the column order and the limits (`69-BOARDS-SPEC.md` section 2).
- **A move is one line in one file**, entering the change queue (`69-BOARDS-SPEC.md` section 3.1).
- **A limit warns and never blocks.** `Doing 4 / 3` turns the count to the warning colour and nothing
  else (`69-BOARDS-SPEC.md` section 4.1).
- **An agent never moves a card.** Its move is drawn as a pending change: the card ghosted in the
  target column, while the real card stays where the file says it is (`69-BOARDS-SPEC.md` section 5).
- **An agent's move is never one click to accept.** As on S20, the diff comes first. The ghost card
  offers Show diff and Reject; Accept appears beside the diff (S20, "Agent item").
- **Filters are the viewer's own and never written** (`69-BOARDS-SPEC.md` section 4.2).

Doing 4, Review 2, Done 3, which is 3 + 3 + 4 + 2 + 3 = 15. Doing has a limit of 3, so it reads
`4 / 3` in the warning colour. One agent, named by the person as Claude Code on my laptop, proposes
moving Deposit by UPI from Doing to Review. Its due date, 17 September, is before today's 19
September in the drawing, so it is marked overdue. Review's count stays 2 because the ghost is not
a card until accepted.

## Data contract

What | Direction | Port or store | Shape | When
Board file | read | `ProjectFiles.read(path)` | `{ board, cards, key, columns, limits }` from front matter | On open
Card files | read | `ProjectFiles.list(folder)` then `read` | Each card's front matter and first H1 | On open, and on every change in the folder
Board model | derived | `new:board-project` in the domain layer | Columns with ordered cards, an Other column, counts, limits | On every read. Stateless
Pending moves | read | `ChangeQueue.forFolder(folder)` | Items whose span is a card's `status` or `order` line | On open, and on every arrival
A move | write | `ProjectFiles.splice(path, keyLine, bytes)`, as a queue item | One `status` line in one card | On drop, or on Accept of a pending move
A reorder | write | the same splice | One `order` line in one card (`69-BOARDS-SPEC.md` section 3.2) | On drop within a column
A field edit | write | the same splice | One `assignee` or `due` line | On change in the panel
A new card | write | a `create` queue item | A new file with `status` set to that column | On New card
Filter state | read and write | per viewer, local only | `{ mine, dueThisWeek, label, text }` | Never sent, never written

**None of this is built.** At `cb7c16f` there is no board parser and no board view in `src/`. The
front matter writer exists, and `69-BOARDS-SPEC.md` section 3.1 names the defect in it that gates
every move: a `set` deletes the blank lines after the key. The queue has no `create` kind yet.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Move a card | Drag to another column, or the card menu's Move to | One queue item setting `status`. A person's own move is applied on drop as any edit of theirs is | The `status` line cannot be addressed, so `E004` or `E009` refuses and the card stays | `new:ev-board-card-moved`
Move past a limit | The same, into a full column | Written as any move. The count turns to the warning colour | none. A limit never blocks | `new:ev-board-card-moved`
Reorder | Drag within a column | One `order` line in that card | No number fits between the neighbours, so each renumbered card is its own grouped item | `new:ev-board-card-reordered`
Open a card | Click, or Enter on a focused card | The card panel opens beside the board | Card file missing, so `E105` and the card is marked stale | `new:ev-board-card-opened`
Show diff | On a pending move | The panel opens on that card with the diff. Accept appears only there | Proposed bytes missing, so `E027` and the item closes as stale | `doc.change.diff.shown`
Accept a move | Accept in the panel | The `status` line is spliced, the card moves, the ghost goes | The line moved under it, so `E026` refuses and the item stays | `doc.change.accepted`
Reject a move | Reject on the ghost or in the panel | The item closes. The card file is untouched | none | `doc.change.rejected`
Reply | Reply in the panel | A comment against the card. The move stays waiting | none | `doc.change.replied`
Filter | A chip, or text in the search | Cards that do not match are hidden from this viewer | none | `new:ev-board-filtered`
New card | New card at a column's foot | A new file with that column's `status`, as a `create` item | The folder is missing, so `new:board-missing-folder` | `new:ev-board-card-created`
Edit a field | A field in the panel | One line in the card | As for a move | `new:ev-board-field-edited`
Show the source | The MD side of the switch | The board file as markdown | none | `new:ev-board-plain-toggled`

## States

State | When | What is shown | What the person can do
first-run | The first board on this account | One line: a card is a file, and a move changes one line in it | Read it, then work.
empty | A board whose folder holds no cards | The columns with New card in each | Make a card, or make a board from a blueprint on S15.
loading | The folder is being read | The toolbar and the column headers render. Cards fill in | Wait.
partial | Some card files cannot be parsed | Those files sit in the Other column with their reason | Open one and fix it.
offline | No connection, web only | The board is readable. Moves queue as S24 does | Keep working.
unauthorised | The viewer's role may not write | Cards cannot be dragged. Filters work. Accept is absent on pending moves, Reply stays | Read, filter, reply.
over-cap | The account is over its document cap, S33 | Moves and field edits work. New card is blocked, since it creates a document | Move cards, or free space.
AI-unavailable | n/a. Nothing on this screen calls a model. Make a board is on S15 | n/a | n/a.
conflict | Two moves of one card, or a move whose line changed under it | The pending move is marked stale with its original text. Serious cases go to S31 | Reject it, or resolve on S31.
error | The board file cannot be read as a board: a missing version, two columns with one name | The board file opens as a note with the reason, `new:board-version` or `new:board-duplicate-column` | Fix it in MD.
degraded | `limits` and `columns` differ in length | The board shows no limits, and the problems panel names the key, `new:board-limits-mismatch` | Fix the board file.

## Keyboard and focus

key | does
Arrow keys | Move focus between cards and columns
Enter | Opens the focused card's panel
Escape | Closes the panel and returns focus to the card
Option or Alt Shift Up, Down | Moves the focused card to the top or bottom of its column, as `SCREEN-REFERENCES.md` section 3 records from Linear
Cmd or Ctrl Shift Left, Right | Moves the focused card one column. A modifier, because it writes
Tab, Shift Tab | Inside the panel, through the fields, then Show diff or Accept, Reject and Reply

**Focus on arrival is the first card of the first column.**

**Space does not peek.** Linear peeks at a card with Space (`SCREEN-REFERENCES.md` section 3), but
this workspace draws Space as the Ask AI key, so Enter opens the panel instead. Recorded for
`15-INTERACTION-AND-KEYBOARD.md`'s owner.

**Accept and Reject are never on a bare key**, as `15-INTERACTION-AND-KEYBOARD.md` requires and S20
follows. Every key above that writes carries a modifier.

## Responsive

- **One column at a time.** A row of pills switches columns, each with its count, and the current
  one filled. A swipe moves to the next column, and dots show where you are. `69-BOARDS-SPEC.md`
  section 4.4 records this as the proposal for the phone.
- **The limit stays in the column's heading**, in the warning colour, and in the pill.
- **A pending move shows inside the real card** with Show diff and Reject, since there is no second
  column on screen to ghost it into.
- **The card panel becomes a full screen** with the fields, the proposed change, three full-width
  equal controls, the acceptance list and Open as a document.
- **Moving a card** is the card menu's Move to, a bottom sheet of columns. Dragging between columns
  is not offered on the phone.
- **Not on the phone:** adding, renaming or reordering columns, and setting limits.

## Desktop differences

- **A watched folder makes the agent source real.** An agent that edits a card file on disk enters
  the queue as a pending move, the same as on S20.
- Everything else is identical.

## What this screen must never do

- **Never move a card for an agent.** A pending move changes nothing until a person accepts it.
- **Never accept an agent's move before its diff is shown.**
- **Never block a move because a column is over its limit.**
- **Never write a filter**, a column width or a collapsed column into any file.
- **Never rewrite a card file** to move it. One line changes.
- **Never refuse a status value the board does not know.** The card sits in Other.
- **Never show a sprint, a story point or a burndown** (`69-BOARDS-SPEC.md` section 9).
- **Never make Accept more prominent than Reject.**
