# S39. Sheet

> **Where the ids come from.** Every `C`, `E`, `A` and `K` id below already lives in its register:
> `14-COMPONENT-INVENTORY.md`, `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md` and
> `16-COPY-DECK.md`. An id written `new:` plus a slug is a proposal. None of them is in a register
> yet, and "Register rows needed" at the foot lists every one for its owner.

> **What this screen draws.** The format, the formulas and the refusals belong to
> `68-SHEETS-SPEC.md`. This file says only how a person meets them. Where the two disagree,
> `68` wins and this file is the one to fix.

## Purpose

Work with a table in my document the way I would in a spreadsheet, and still have a plain
markdown table in the file that every other tool can read.

## The rules this screen carries

- **A sheet is a table in a document, not a new file type.** The grid edits a GFM pipe table. Its
  formulas live in an `fm-sheet@1` block directly under the table (`68-SHEETS-SPEC.md` sections 2.1
  and 3).
- **Formulas name columns, never cells.** The formula bar reads `= Qty * Price`. There is no `B2`
  anywhere on the screen, because an address like that goes stale when a row is added
  (`68-SHEETS-SPEC.md` section 4, and section 10's never-build list).
- **Viewing never writes.** Sort, filter, row numbers, column widths and the frozen header all
  change the view and never the file (`68-SHEETS-SPEC.md` section 6.1). The toolbar says so in one
  line, so nobody has to wonder.
- **Typing into a cell changes that cell's bytes and nothing else.** The diff for one edit is one
  line (`68-SHEETS-SPEC.md` section 5.1).
- **A summary is drawn and never written.** The `sum` under the grid comes from a `foot.` formula and
  is not a row in the file.

**What the drawing holds, so nobody re-derives it.** Six rows from `launch-costs.md` in the
Zephyrus booking project, sorted by Total, high to low, in the view only. Each Total is Qty times
Price, and the sum under the grid is 38720: 900 + 300 + 320 + 19200 + 15000 + 3000. The row
`WhatsApp template messages` is 400 times 0.8, which is exactly 320 in decimal, the case
`68-SHEETS-SPEC.md` section 4.5 exists for. On the phone, Price for Design hours is being changed
from 1200 to 1100, so its Total becomes 16 times 1100, which is 17600.

## Data contract

What | Direction | Port or store | Shape | When
Table bytes | read | `ProjectFiles.read(path)` | The document, from which the table and the block under it are parsed | On open
Parsed sheet | derived | `new:sheet-parse` in the domain layer | `{ headers, rows, formulas: { col, foot }, types }` | On every read. Stateless, so the grid is a projection
Computed values | derived | `new:sheet-evaluate` in the domain layer | One value or one error per computed cell, and one per summary | On every read. Deterministic, `68-SHEETS-SPEC.md` section 4.7
A cell edit | write | `ProjectFiles.splice(path, cellRange, bytes)` | One cell's bytes, escaped per `68-SHEETS-SPEC.md` section 5.3 | On Enter, Tab, blur or Save
A computed cell after an edit | write | the same splice, one per dependent cell | One cell's bytes each | With the edit that caused it
A structure edit | write | the same splice | One line for a new row; every row for a new column (`68-SHEETS-SPEC.md` section 5.4) | On the control
View state | read and write | per viewer, local only | `{ sort, filter, widths, frozen }` | Never sent, never written to the file
Entitlement | read | `limitsFor(account)` | Whether the document may be written | On open

**None of this is built as drawn.** At `cb7c16f` the shipped `C045` writes through `setTableCell`,
which re-serialises the whole table. `68-SHEETS-SPEC.md` section 5.1 names the three defects that
break the one-cell rule, `TD-024`, `TD-025` and `TD-026`, and says the grid cannot ship until they are
fixed. There is no evaluator and no `fm-sheet@1` parser in `src/`.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Edit a cell | Type into a focused cell, then Enter or Tab | That cell's bytes are spliced. Dependent computed cells are recomputed and spliced one each | Row width differs from the header's, so `E500` refuses and nothing is written | `new:ev-sheet-cell-edited`
Type a line break into a cell | Shift Enter in a pipe-table cell | Refused. GFM cells are single-line | `new:sheet-cell-linebreak` | `new:ev-sheet-refused`
Sort the view | The sort chip, or a column header's menu | The rows are drawn in the new order. The file is untouched | none | `new:ev-sheet-view-changed`
Filter the view | The filter chip | Rows that do not match are hidden from this viewer | none | `new:ev-sheet-view-changed`
Sort the file | The column menu's Sort the file, kept apart from the chip | One queue item that reorders the rows between the first and the last that moved | Any row cannot be located, so `E026` refuses and the file is unchanged | `new:ev-sheet-file-sorted`
Add a row | The add-row row, or Enter on the last row | One new line under the focused row | none | `new:ev-sheet-structure`
Add a column | The plus at the end of the header, then a name and a type | One cell appended to every row and to the delimiter row | A name that another header already has, so the column is not added and the reason is shown | `new:ev-sheet-structure`
Set a row formula | The formula bar, on a column | A `col.` line is added or changed in the block under the table, then the column is computed | A formula that refers to itself, so `new:sheet-formula-cycle`; an unknown function, so `new:sheet-formula-unknown-function` | `new:ev-sheet-formula-set`
Show the source | The MD side of the switch | The table and its `fm-sheet@1` block shown as markdown, in place | none | `new:ev-sheet-plain-toggled`
Open as a sheet | On an embedded table | The same table full width, in its own view of the same file | none | `new:ev-sheet-opened`
Toggle a checkbox cell | Click or Space on a `[ ]` or `[x]` cell | That cell's three bytes change | none | `new:ev-sheet-cell-edited`

**A formula that meets text shows an error in that cell and writes nothing.** A cell such as `1,200`
is text by `68-SHEETS-SPEC.md` section 4.4, so the row's Total shows `new:sheet-formula-not-number`
and its bytes in the file are left as they were.

## States

State | When | What is shown | What the person can do
first-run | The first time a table is opened as a sheet on this account | One line under the toolbar: the view never writes, and a cell you type into does | Read it, then work.
empty | A table with a header and no rows | The header, the add-row row, and an empty summary | Add a row.
loading | The document is being read | The toolbar and the header render. Rows fill in | Wait.
partial | Some computed cells cannot be evaluated | Those cells show their error. Everything else computes | Fix the input cells.
offline | No connection, web only | The grid is editable. Edits queue as the workspace does on S24 | Keep working.
unauthorised | The viewer's role may not write | The grid is readable. Cells do not take focus for editing. Sort and filter still work | Read, sort, filter.
over-cap | The account is over its document cap, S33 | Readable and exportable. Edits that would create a document are blocked; edits to this one are not | Carry on, or free space.
AI-unavailable | n/a. Nothing on this screen calls a model | n/a | n/a.
conflict | A computed cell in the file disagrees with its formula, because it was edited elsewhere | Both values shown, and a recompute offered as a queue item. **Opening never writes** (`68-SHEETS-SPEC.md` section 7) | Accept the recompute on S20, or leave it.
error | The `fm-sheet@1` block cannot compute | The block renders its source and the reason, `E501`. The table stays editable as a plain table | Fix the block in MD.
degraded | More rows than fit the keystroke budget | `UNVERIFIED:` the threshold is unmeasured, `new:sheet-row-budget`. No number is drawn until one is measured | n/a until measured.

## Keyboard and focus

key | does
Arrow keys | Move the focused cell
Enter | Edit the focused cell, then commit and move down
Tab, Shift Tab | Commit and move right or left
Escape | Cancel the edit in progress; a second Escape leaves the grid for the toolbar
Space | Toggles a focused checkbox cell. Elsewhere it is the AI launcher's key, see below
Cmd or Ctrl Enter | Commit without moving
Cmd or Ctrl Shift M | The Grid and MD switch. `UNVERIFIED:` checked against no binding in `15-INTERACTION-AND-KEYBOARD.md`; needs a row there

**Focus on arrival is the first cell of the first row**, not the toolbar, so typing starts at once.

**Space conflicts, and the grid wins while it has focus.** The workspace draws Space as the Ask AI
key (`rail()` at `docs/mvp0/screens/gen.mjs:988`). Inside a focused grid, Space toggles a checkbox
or types a space. The AI launcher stays reachable from its button. Recorded for
`15-INTERACTION-AND-KEYBOARD.md`'s owner.

**No bare letter changes the file.** Typing starts an edit of the focused cell, which is the
spreadsheet convention, and it is committed only by Enter, Tab or blur.

## Responsive

- **The first column is pinned** and the rest scroll sideways. A one-line note says which columns are
  a swipe away.
- **A cell is edited in a bottom sheet**, `C068`, never in the cell itself: a large field, its type,
  the values that depend on it, Previous, Next and Save. `SCREEN-REFERENCES.md` section 2 records
  this as `INFERENCE:` from Airtable's expanded record.
- **The formula bar is folded into the sheet's header of the editor**: the focused column's formula
  appears in the cell editor rather than above the grid.
- **Rows are 40 px tall** so a thumb can hit one.
- **Not on the phone:** adding a column and setting a formula. Both need the desktop or a tablet.

## Desktop differences

- **A `.csv` on disk opens in place**, because the desktop build reads the file system.
- Everything else is identical.

## What this screen must never do

- **Never show an A1 address**, in the formula bar or anywhere else.
- **Never write when a person only looks**: sort, filter, widths, row numbers and freezing are views.
- **Never re-pad or re-align a table** to make it tidy. A one-cell edit is a one-line diff.
- **Never write a summary into the file.**
- **Never write on open**, even when a computed cell is wrong. Offer the recompute as a change.
- **Never accept `=` typed into a cell as a formula.** It is text, and a formula lives in the block.
- **Never hide a column from a reader of a published sheet.** A filter is not a wall.
- **Never merge cells, colour cells or add a second tab** to a sheet (`68-SHEETS-SPEC.md` section 10).
