**Why sgnk-md is the one, and what it actually costs.** The mechanism is not thematic. 1. **The identity migration is half-done and it is in the shipping product.** `frontmatter/src/modules/auth/index.ts` adds the Firebase path with the comment "the identity system that replaces Auth.js" — while `auth-options.ts` still runs `isAllowed(ghProfile?.login, authEnv.ALLOWED_GH_LOGIN)` in the sign-in callback, with `ALLOWED_GH_LOGIN` defaulting to `"sagnikmitra"` [measured, `config/env.ts:47`, `auth-options.ts:82`]. Two identity systems, one of which is a single-person allowlist, inside the product meant to serve 10,000 users. Finish or delete one. ~1 week.
2. **md has CI and frontmatter does not** [per the record's D1 row]. Port `ci.yml` first, before any of the above. ~1 day.

One methodological flag: the ecosystem doc's own "last active" dates lag reality. It records md at 2026-06-06 and HQ at 2026-06-05; git says 2026-07-17 and 2026-07-03 [measured]. Prefer git. Where I quote a doc date above I have said so.

**The trap, precisely.** It does not arrive as a decision to build a platform. It arrives as four small, individually reasonable steps, and it is already two of them in.

*Step one: the surface that is not the product grows faster than the product.* frontmatter today holds **2,086,656 words across 248 markdown files** of documentation against **38,483 lines of source and test** [measured] — roughly **54 words of plan per line of code** [derived]. Nine PDFs of the same plan at different versions. The planning artifact is the largest thing in the repository. This is the ecosystem's characteristic failure in miniature: producing a beautiful, complete, superseded description of a thing instead of the thing.

*Step two: a NO gets re-argued as a YES because the code exists.* HQ has a billing table, so billing "is done". CareerOS has entitlements, so metering "is done". skills-registry syncs markdown, so projection "is done". Each is true and each is a trap, because adopting the code means adopting its data model, its migrations, its on-call surface, and its 33 modules. The cost of reuse in this portfolio is not the integration, it is the permanent addition to what one person must keep alive at 3am.

*Step three: the pitch generalises.* "A markdown editor whose file is the only source of truth" becomes "a document engine", then "a content OS", then "the substrate for the whole sgnk suite". Each generalisation is one sentence longer and one buyer smaller. The market is not short of markdown editors — 467 HN stories match "markdown editor" and 357 comments match "obsidian alternative" [fetched, hn.algolia.com, 2026-08-31]. The only thing that distinguishes frontmatter in that crowd is 3,614 lines of splice engine that refuses rather than guesses. A platform pitch hides exactly that.

*Step four: nobody notices, because everything still returns 200.* Twelve live domains, one active developer, and no customer on any of them. Dormancy is invisible until a sales demo hits a paused Supabase project or a 525.

The recognisable symptom, so you can catch it: **the moment a roadmap item is justified by "we already have that in HQ / CareerOS / skills-registry" rather than by a user who asked for it, the trap has closed.** The counter-move is the one this round asks for — the answer to "does it fuse?" is NO twenty times, YES once, and the YES is a deletion.
