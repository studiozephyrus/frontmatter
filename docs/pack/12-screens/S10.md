# S10. Problems

> A checker and a formatter in the box, so nobody installs eleven tools to find a broken link. The
> founders said build what is there, and added one rule about mixing machine work with opinion.

> **Where the ids come from.** Every `C`, `E`, `A` and `K` id below lives in its register:
> `14-COMPONENT-INVENTORY.md`, `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md` and
> `16-COPY-DECK.md`. The ids this screen first proposed were reconciled into those registers on 18
> September 2026. The old-to-new mapping is in `tools/error-map.json`, `tools/component-map.json`
> and `tools/acceptance-map.json`, and `tools/validate-pack.py` fails if any id here has no home.

## Purpose

Show what is wrong with the open document, keep a deterministic finding apart from an opinion, and
charge nothing for the half that needs no model.

## The filter, and how the founders' instruction landed here

`docs/mvp0/SCREEN-CHANGES-2026-09-18.md:80` asked for two toggles, given in the review's own words
as human reviews and AI reviews. `:296` then generalised it:

> Toggles everywhere, on both S10 and S20. Wherever human and AI work sit together, split them with
> a toggle rather than combining them into one list.

**The general rule is the instruction; the labels are per screen.** On S20 the split is People
against AI and agents, because that screen holds work by both. On this screen nobody is reviewing
anything, so the same rule splits the two kinds of finding instead.

**The filter is All, Checks, Writing.** `docs/mvp0/SCREENS.md:129` states it and gives the reason: a
deterministic finding and a model's opinion are never mixed into one list.

Segment | What is in it | Blocks | Costs
All | everything, in document order | no | nothing beyond what the two below cost
Checks | structural findings, each one true or false | no | **nothing, ever**
Writing | advisory notes on the prose | **never** | see D28

### The checks that ship, and what each costs

The plan's reason for shipping a checker at all is that markdownlint and Prettier are among the
most installed extensions on Visual Studio Code, so a checker and a formatter are expected rather
than impressive. `[M]` re-derived 18 September 2026 at 17:37 UTC from the Marketplace's
`extensionquery` API: `DavidAnson.vscode-markdownlint` 12,192,430 installs, `esbenp.prettier-vscode`
71,662,765. The plan quotes 12,180,750 and 71,626,148 from an earlier reading.

Check | Kind | Severity | Needs a model | Cost
Link goes nowhere | structural | error | no | nothing
Heading level skips | structural | warning | no | nothing
Image has no alt text | structural | warning | no | nothing
Table row width does not match the header | structural | warning | no | nothing
Spelling, against a project dictionary | structural | warning | no | nothing
Front matter schema | structural | warning | no | nothing
A sentence far longer than the rest | advisory | advisory | no (D28) | nothing

- **Spelling and the front matter schema are in because they are the two most-installed checks in
  the world and neither needs a model.** That is the plan's own reasoning and it is why they are not
  a later feature.
- The drawn example carries five findings, four Checks and one Writing, each one true of the
  document beside it. A panel that shows a finding the document does not have is worse than no
  panel.

### The sales line, and why it is on the screen

**Structural checks run on the device and cost nothing.** The plan states the alternative: eleven
separate tools, four package managers and nine configuration files to get this elsewhere, or open
the file.

`C130` carries that fact in one sentence. It is on the screen rather than on a marketing page,
because the moment a person is looking at a list of problems is the moment the claim is checkable.

### Fix all safe

Safe means the fix cannot be wrong. A fix qualifies only when the correct replacement is derivable
from the document alone.

Finding | Safe to fix automatically | Why
Table row width | yes | the header defines the width
Heading level skip | yes | the missing level is determined by its neighbours
Trailing whitespace and fence hygiene | **no, the formatter's job** | it touches lines with no finding (D29)
Image alt text | **no** | only the author knows what the image shows
Broken link | **no** | the intended target is a guess
Spelling | **no** | a name is not a misspelling
A long sentence | **no** | it is an opinion

- **Fix all safe states the count before it acts**, and applies the fixes as one splice batch with
  one undo step.
- If nothing is safe, it says so rather than doing nothing silently, which is `E507`.

## Data contract

What | Direction | Port or store | Shape | When
Open file bytes | in | `DocumentReader.open(path)` | `{bytes, version, headHash}` | on mount
Findings | in | `CheckRunner.run(bytes, rules)` | findings with byte ranges and severities | on parse, debounced
Link targets | in | `GraphReader.resolve(link)` | a path, or nothing | per link finding
Project dictionary | in | a file in the project | a word list | on mount, and when it changes
Front matter schema | in | a file in the project | a schema | on mount
Rules | in and out | a file in the project | the rule set | read on mount, written from `C061`
A fix | out | `DocumentWriter.splice()` | a byte range and its replacement | on Fix all safe, or a row's own fix

- **`CheckRunner` runs on the device.** No document bytes leave the machine for the Checks segment,
  which is what makes it free and what makes it work offline.
- **The rules are a file in the project**, so they travel with the documents, can be reviewed in a
  pull request, and are not a hidden account setting.
- The dictionary is a file too, for the same reason. A name added on one machine is a name
  everywhere.

## States

State | When | What is shown | What the person can do
first-run | the first time the panel opens | the list, plus `C130` | read, fix, open Rules
empty | no findings | a plain line saying the document is clean, with the filter still visible | keep writing
loading | the first run on a large document | the filter, and the list area reserved | keep writing; checks never block typing
partial | Checks done, Writing not | the Checks findings, and the Writing count pending | filter to Checks and work
offline | no network | **everything in Checks works** | fix; Writing is unavailable and says so
unauthorised | the role cannot edit | findings shown, fixes disabled | read, export
over-cap | over the credit cap | Checks unaffected; Writing disabled with the reason | fix the structural findings, which are free
AI-unavailable | the chain is down | Checks unaffected; the Writing segment says so | the same
conflict | the document has an unresolved conflict | the panel opens; fixes are disabled | resolve on S31 first
error | a check threw | that check's findings are absent and `E029` names which check | the other checks still ran
degraded | the dictionary or the schema is missing | those checks are skipped and say so, rather than flooding the list | add the file, or ignore

**A failed check never removes the other checks' findings.** One broken rule does not blank the
panel.

## Keyboard and focus

- The panel opens with focus on the filter, because the first decision is which half to look at.
- Up and down move through findings. Enter opens the focused one in the document.
- Left and right move between the three filter segments.
- Escape closes the panel and returns focus to the caret.
- There is no shortcut that applies a fix without a visible confirmation of what it will do.
- The full map is `15-INTERACTION-AND-KEYBOARD.md`.

## Responsive

- The panel becomes the right drawer, over a backdrop, reached from More in the bottom bar.
- The filter stays. It is three short words and it is the founders' instruction, so it is not the
  thing that gets dropped for width.
- Fix all safe stays in the drawer's foot; Rules moves into the drawer's own overflow.
- A finding's line number stays visible, because it is how a person finds the place on a small
  screen.

## Desktop differences

- The checks run on the device in both builds. The desktop build has no document-size ceiling, so
  `E504` is a web-only state.
- The Writing segment can run on a local model on the desktop, so it is available offline there.

## What this screen must never do

- **Never mix a deterministic finding with an opinion in one undifferentiated list.** That is the
  founders' rule, generalised on 18 September to every screen where the two kinds sit together.
- **Never charge a credit for a structural check.**
- **Never send document bytes off the device to run a structural check.**
- **Never let a writing note block a save, an export, a publish or a commit.**
- **Never auto-fix something only the author can know**: alt text, a link target, a proper noun.
- **Never apply a batch of fixes without stating the count first.**
- **Never blank the panel because one check failed.**
- **Never hide the rules in an account setting.** They are a file in the project.
- **Never invent a finding.** Every row is true of the open document at the line it names.
- **Never use an emoji as a severity marker.** The dot is a shape and a colour, with text beside it.

### Resolutions

- **D28, resolved (proposed 18 Sep, founder review). Rules-based, on the device, and free.** The one
  advisory drawn, a sentence far longer than the rest, is a measure of the document itself. So `C130`
  stays true without a caveat. The founders kept the Checks and Writing split as drawn
  (`docs/mvp0/REVIEW-COVERAGE-2026-09-18.md` section 7, row 26).
- D28, rejected: a model-backed Writing segment, which would charge a credit on a panel that
  recomputes on every reopen. `docs/mvp0/SCREENS.md:129` still calls it a model's opinion and needs
  the same correction; that file is not this agent's.
- **D29, resolved (proposed 18 Sep, founder review). The formatter is a separate command**, `F148`,
  on the command palette. Fix all safe touches only the lines that carry a finding. The table above
  now says so for whitespace and fence hygiene.
- D29, rejected: folding the formatter into Fix all safe, which would rewrite lines the person was
  never shown a finding for, on a product that never changes bytes it was not asked to.
- **D30a, resolved (proposed 18 Sep, founder review). `.markdownlint.jsonc` at the project root.**
  Three of the six checks are markdownlint rules already: `MD001` heading increment, `MD045` alt
  text and `MD056` table column count. The rules then travel to every tool that reads that file.
- D30a, the evidence. `[M]` markdownlint's README and markdownlint-cli2's README on GitHub, opened
  18 September 2026, list those three rules and the `.markdownlint.jsonc` file name.
- D30a, what it leaves. The project dictionary and the front matter schema do not fit that file.
  Their homes need a row in `66-FORMAT-SPECIFICATIONS.md`, which this agent does not own. Rejected:
  a private `.frontmatter/` rules file, which no other tool reads.
