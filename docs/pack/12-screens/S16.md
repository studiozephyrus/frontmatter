# S16. The map

> **Ids invented here.** This file reserves `C160` to `C169`, `E160` to `E169`, `A160` to `A169` and
> the `K.s16.*` namespace, on the rule that the two digits after the letter are the screen number.
> **UNVERIFIED:** the registers those ids point into did not exist at `0af3c90`, so every id is a
> proposal for them.

## Purpose

See which document governs what, and which decision put it there, without reading all twelve of them.

## Entry and exit

Direction | How | Route or control
In | The view selector on the toolbar, set to Map | `C043`, then `/p/<projectId>/map`
In | The map row in the kit rail on S15 | `C150`
In | Opening `MAP.md` from the tree, which offers the graph beside the text | `C042`
Out | Clicking a node, which opens that file as a document | S04
Out | Clicking a decision node, which opens the decision record at that heading | S04, scrolled to the heading
Out | The view selector, set to Page or any other view | `C043`
Out | Back to the kit | S15

**The map is a view, never a route of its own with its own state.** It sits in the same view selector
as Page, Flow, Slides, Mind map, Kanban and Outline.

**Four node kinds, four colours**, from `KCOL` at `docs/mvp0/screens/gen.mjs:1274`.

kind | what it is | stroke
`doc` | A markdown document in the kit | The foreground colour, at a heavier stroke
`spec` | A file under the specs folder | The link colour
`why` | A decision that explains a document or a spec | The success colour
`agent` | An instruction file an agent loads | The accent colour

**Colour is never the only signal.** Each node also carries its kind in its accessible name, because a
graph that only encodes kind as a stroke colour fails at 4.5:1 and fails for anyone not seeing colour.

## Data contract

what | direction | port or store | shape | when
Project files | read | `ProjectFiles.list(projectId)` | Paths and bytes | On arrival, and on every save
Parsed links | read | `LinkIndex.forProject(projectId)` | `{ from, to, kind }` | Derived from the files, never stored as truth
Decision links | read | `DecisionIndex.forProject(projectId)` | `{ decisionId, heading, governs: [path] }` | Parsed from the decision record
Graph | derived | `buildGraph(notes)` | `{ nodes: GraphNode[], links: GraphLink[] }` | Rebuilt on every save, in the browser
Counts | derived | the same build | `{ documents, dataFiles, links, orphans }` | With the graph
Kit copies | write | `KitStore.publish` | `MAP.md` and `graph.json`, written into the kit | On a blueprint publish

**Part of this is built.** `buildGraph`, `GraphNode`, `GraphLink`, `GraphData` and `COLORS` are
exported from `src/modules/graph/index.ts` at `0af3c90`, with the implementation in
`src/modules/graph/presentation/graph-data.ts`. Its grouping is the vault's tag groups and not the
four kit kinds above, so the kinds are **specified, not built**.

**The map is a projection and never a second source of truth.** It is rebuilt from the files on every
save. Nothing on this screen is stored and read back. That is the plan's own rule at
`docs/mvp0/PRODUCT-PLAN.md:502`, and it is why the map costs no credits, at
`docs/mvp0/PRODUCT-PLAN.md:499`.

## Actions

action | trigger | what happens | failure behaviour | event id
Open the map | The view selector, or the kit rail row | The graph is built from the files and drawn | A file fails to parse, so `E160` names it and draws the rest | `map.opened`
Open a node | Click, or Enter on a focused node | That file opens as a document | Path no longer on disk, so `E161` names it and offers a rebuild | `map.node.opened`
Open a decision node | Click a decision node | The decision record opens at that heading | Heading missing, so `E162` opens the file at its top and says why | `map.decision.opened`
Hover a node | Pointer, or focus | Its direct edges are emphasised and the rest dimmed | none | `map.node.focused`
Rebuild | A save anywhere in the project | The graph is rebuilt and redrawn | Build exceeds the node budget, so `E163` draws the reachable subgraph and says so | `map.rebuilt`
Change the view | The view selector | Another projection of the same bytes | none | `map.view.changed`
Copy the counts | The counts in the toolbar | The three counts go to the clipboard as text | Clipboard refused, so `E164` shows them to select | `map.counts.copied`

**Nothing on this screen writes to a document.** Every action is a read or a navigation. The two kit
copies are written by S15's publish, not here.

## States

state | when | what is shown | what the person can do
first-run | The first map on this account | One line saying what the map is for | Read it, or carry on.
empty | A project with one file and no links | The single node, and a line saying links appear as documents refer to each other | Write, or import more.
loading | The graph is being built | The counts render first, the canvas after | Wait. Builds are local and fast.
partial | Some files failed to parse | The parsed subgraph, with the failed paths named | Open a failed file, or rebuild.
offline | No connection | Unchanged. The build is local and needs nothing | Everything.
unauthorised | The project belongs to another account | `E165`, and no graph | Go back.
over-cap | n/a. The map costs no credits and no quota | n/a | n/a.
AI-unavailable | n/a. No model is called to build a map | n/a | n/a.
conflict | A file changed on disk under an open map | The map rebuilds from the new bytes. Conflicts belong to S31 | Resolve on S31.
error | The build itself threw | `E166`, with the last good graph kept on screen and marked stale | Rebuild, or open the files.
degraded | More nodes than the budget allows | The subgraph reachable from the brief, with the number left out named | Filter, or open the document list instead.

## Keyboard and focus

key | does
Tab, Shift Tab | Moves through the nodes in the order the build emitted them
Enter | Opens the focused node
Arrow keys | Moves to the nearest node in that direction
Escape | Returns focus to the toolbar
V | Opens the view selector

**Focus on arrival is the node for the brief**, which is the root every other node hangs from.

**Every node is a focusable element with an accessible name** carrying its label and its kind. An SVG
graph that is one unlabelled picture is unusable by keyboard and unreadable by a screen reader, and
this screen exists to be read.

**UNVERIFIED:** collisions with `15-INTERACTION-AND-KEYBOARD.md` could not be checked. That file did
not exist at `0af3c90`.

## Responsive

- **The chip row replaces the view selector** at phone width, with Page, Map, Flow and Outline
  scrolling sideways.
- **The graph scales to the width** and keeps its aspect, at `width:100%;height:auto`.
- **The rail counts move under the graph** as a single line.
- **Hover has no phone equivalent**, so a tap selects a node and shows its edges before a second tap
  opens it. A one-tap open would make the graph unreadable on a phone.
- **Nothing is unavailable at phone width**, though a project past about forty nodes is easier to read
  on the desktop.

## Desktop differences

- **The graph can be exported as an SVG file** to disk, because the desktop build has the file system.
- Everything else is identical. The build is local in both.

## Acceptance

id | criterion | test id
`A160` | Every node in the graph corresponds to a file that exists on disk at build time | `T-S16-nodes-exist`.
`A161` | The three data files in a kit are counted as files and drawn as nodes nowhere | `T-S16-data-not-nodes`.
`A162` | The counts in the toolbar, the tree foot and the rail are one derivation, never three | `T-S16-counts-one-source`.
`A163` | A save anywhere in the project rebuilds the graph with no model call and no credit | `T-S16-no-model-call`.
`A164` | Every node is reachable by keyboard and carries a name that includes its kind | `T-S16-a11y-nodes`.
`A165` | A file that fails to parse is named, and the rest of the graph still draws | `T-S16-partial-parse`.
`A166` | A failed rebuild keeps the previous graph on screen and marks it stale | `T-S16-stale-marked`.
`A167` | The graph is inline SVG, with no image element and no canvas element | `T-S16-inline-svg`.

## What this screen must never do

- **Never store the graph as the truth.** It is rebuilt from the files, every save.
- **Never call a model to draw a map.** Structure is read, not inferred, which is why it is free.
- **Never draw a node for a file that is not there.**
- **Never draw a stale graph without saying it is stale.**
- **Never encode a node's kind in colour alone.**
- **Never ship the map as a binary image.** A diagram that cannot be diffed as text is not a source
  of truth, per `docs/pack/65-CONVENTIONS.md:126`.
- **Never let a map action write to a document.** The map reads.
