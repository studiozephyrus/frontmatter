# S32. AI unavailable

> **Invented identifiers.** The registers this file points into are being written in parallel. Ids
> follow `65-CONVENTIONS.md` section 3 on a stated scheme: components `C320` to `C329`, errors
> `E320` to `E329`, acceptance `A320` to `A329`. `C900` upward is shared across S27 to S38. Copy
> ids are namespaced `K.s32.*`.

## Purpose

Every provider refused, my document is untouched, my credits are untouched, and here is what I can
do instead.

## Entry and exit

**This screen is never an apology.** It is the state in which the product still offers something,
and the founders' decision of 18 September gave it the thing to offer.

How a person arrives | What was happening
An AI edit on a selection | Every provider in the edit chain refused or timed out
The AI box on a document | The same, on the document chain
Starting a blueprint | The blueprint chain refused, so the standard question set is offered instead
Turning a page in idea mode | A rewrite could not be generated, so the planned questions stand
The right rail | The AI edit control is already disabled with the reason on it

How they leave | What happens
Try again | The chain is re-attempted. A provider whose pool has a stated reset is not tried before it
Use a standard question set | Idea mode continues with the standard set. Nothing waits on a model
Use the local model | Desktop only. The edit runs on the machine and nothing leaves it
Use my own key | Settings, AI, the bring-your-own-key field, when that flag is on in S37
Carry on writing | The document was never touched. The editor is behind this box and works

## The reasons a provider declines, and why the wording differs per row

`[M]` opened 2026-09-18 by the router research, `docs/research/2026-09-18-llm/raw/L3-router-design.md`.
These are the real dialects. A row that says the wrong one is worse than a row that says nothing.

provider | exhausted, meaning stop | transient, meaning try again | what the row can honestly say
Cloudflare Workers AI | 429 with internal code `3036`, the daily free allocation of 10,000 neurons | 429 with internal code `3040`, capacity temporarily exceeded | Both the reason and a true reset, because the limits reset daily at 00:00 UTC. `L3:594` and `:595`
Groq | 429, and the remaining-requests header for the day reaching zero | 429 carrying `retry-after` in seconds | The seconds, when the header is there. **Not** a daily token reset, because no header reports it. `L3:623`
Cerebras | 429 naming which of its two token buckets was exceeded | The same 429 | The bucket, and no reset time at all, because it refills continuously rather than resetting. `L3:636`
SambaNova | Not established in the research | Not established | A timeout or a refusal, and nothing about pools. `UNVERIFIED:` see the note below
The chain | Every row above declined | | The one line at the top

**Three things follow from that table, and each is a build instruction.**

- **The HTTP status alone cannot tell exhaustion from a blip.** Cloudflare returns 429 for both, and
  only the internal code separates them. `L3:598` calls this the single most important sentence in
  that document. A row that reads try again in a moment when the daily pool is gone is a lie the
  screen tells once an hour for the rest of the day.
- **No circuit breaker in the survey measures exhaustion**, only failure, `L3:579`. A provider whose
  pool is finished is not failing. It is correctly saying it is out, and it must not be retried on
  the failure schedule.
- **A reset time is shown only where a provider states one.** Cloudflare states 00:00 UTC. Cerebras
  has no notion of a reset. Groq reports a per-minute token reset and never the daily one. Inventing
  the missing ones would make this screen the most confidently wrong surface in the product.

**A disagreement between two sources, named rather than resolved.** The drawn screen and
`docs/mvp0/PRODUCT-PLAN.md:1171` both put SambaNova in the chain, the plan quoting 20 requests a day
per model from its pages. The free-provider research lists SambaNova among those it never reached,
`docs/research/2026-09-18-llm/raw/L1-free-providers.md:908`. Both can be true, since they are
different sessions opening different pages. Until one of them is re-opened, this screen states
SambaNova's row from a live response and never from a published limit.

## Data contract

what | direction | port or store | shape | when
Attempt outcome | read | `AiRouter.lastAttempt(callId)` | per provider: name, order, outcome, reason code, reset if stated | On rendering this screen
Pool state | read | `ProviderLedgerReader.state()` | per provider: what is left today, and how that was known | On render, and never by making a probe call
Remaining allowance | read | `UsageLedgerReader.currentPeriod()` | the person's remaining edits and blueprints | On render, to state that they are untouched
Retry | write | `AiRouter.retry(callId)` | the same call, re-planned | On the retry control
Fallback question set | read | `QuestionSetReader.standard(template)` | the standard set for the idea's template | On choosing the standard set
Local model | read | `LocalModelPort.available()` | present or not, and which model | Desktop only

**Nothing is written to the document by this screen, ever.** It has no document write in its
contract. That is not an omission.

**No deduction happens on a failed call.** The ledger row of `docs/mvp0/PRODUCT-PLAN.md:1445` is
written when a call is served, not when one is attempted.

## Actions

**The standard question set is the founders' answer to this screen.**

something useful to offer instead of an apology, and `docs/mvp0/PRODUCT-PLAN.md:1241` records the
same. Dynamic questioning is the default and the standard set is the graceful-degradation path, not
a paywall.

## Keyboard and focus

- Focus moves to the failure line when the box appears, so the first thing read is that the document
  is untouched.
- The chain list is read as a list, each row naming its provider and its reason.
- Tab order: retry, then each chip in the order drawn, then dismiss.
- Escape dismisses the box and returns focus to where the person was typing.
- **Nothing here traps focus.** The editor behind is working, and a person who wants to keep writing
  must be able to.

## Responsive

- The chain list keeps one provider per row on the phone. It does not become a summary count.
- The chips wrap to two rows rather than scrolling sideways.
- The desktop and bring-your-own-key chips are hidden on a phone browser, because neither is
  reachable from there, and a chip that cannot be used is worse than no chip.
- `[Z]` the phone view takes the same theme treatment as the desktop,
  `docs/mvp0/SCREEN-CHANGES-2026-09-18.md:19`.

## Desktop differences

- The local model chip is the first way forward rather than the third, because it is the one that
  always works. `docs/mvp0/PRODUCT-PLAN.md:1182` puts a local model on the desktop for edits, with
  nothing leaving the machine.
- With a local model installed and the chain down, the desktop may not reach this screen at all for
  an edit.
- A blueprint still needs the chain, so this screen is reachable on the desktop for that.

## What this screen must never do

- **Never apologise and stop.** `[Z]` the founders' decision of 18 September exists so this screen
  has something to offer. At least one way forward is always shown.
- **Never deduct for a failed call.** The credit note is a promise the ledger has to keep.
- **Never touch the document.** No partial text, no draft of a failed edit, no marker.
- **Never invent a reset time.** Show one only where the provider states one.
- **Never show the same wording for exhausted and transient.** They are different facts and only the
  internal code separates them on two of the four providers.
- **Never retry an exhausted provider on the failure schedule.** `L3:579`: a breaker that treats
  exhaustion as failure will retry a finished key every few seconds for the rest of the day.
- **Never blame the person's document.** The chain list exists so they can see it was not their
  file, which is the generator's stated reason for drawing it.
- **Never show a provider that is not in the chain.** A provider whose terms were not opened is not
  in the chain and has no row here. `docs/mvp0/PRODUCT-PLAN.md:1184`.
- **Never conflate this with S33.** Our failure and their limit are different screens with different
  copy and different exits.
