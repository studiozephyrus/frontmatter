# S11. Instruction files

> This screen was a health panel on one `AGENTS.md`. On 18 September the founders reversed it
> toward the research: it is now the whole instruction-file set. It is also the screen with the
> strictest rule about what it may claim.

> **Where the ids come from.** Every `C`, `E`, `A` and `K` id below lives in its register:
> `14-COMPONENT-INVENTORY.md`, `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md` and
> `16-COPY-DECK.md`. The ids this screen first proposed were reconciled into those registers on 18
> September 2026. The old-to-new mapping is in `tools/error-map.json`, `tools/component-map.json`
> and `tools/acceptance-map.json`, and `tools/validate-pack.py` fails if any id here has no home.

## Purpose

Show every instruction file a project keeps for its agents, say which are linked and which are
copies, and say plainly which of them has drifted.

## The reversal, and the rule it carries

`docs/mvp0/SCREEN-CHANGES-2026-09-18.md:87` recorded the screen as fine as drawn. `:88` flagged it
against the research, and `:303` is the founders' answer:

> S11 follows the research. The one-file health panel becomes the whole instruction-file set.

**Two findings drove it**, both `[O]` from the research round of 18 September:

Finding | What it changed
The loudest artefact in the whole round is 6,644 reactions on a request about **several** instruction files, and a three-tool team keeps four or more | the screen is a set, not a file
Two independent studies find these files do not raise task success, and one measured over 20 per cent added cost | what the screen is allowed to claim

### The claim rule, stated as a rule because it is one

**The screen may say a file is correct. It may not say a file makes an agent better.**

May say | May not say
this file is under the size cap this tool publishes | this file will make the agent follow your rules
the setup commands are present | a tidier file gets better results
this copy is three lines behind its source | tidying this raises task success
these lines restate what a linter already enforces, and cost tokens every session | this file is why the agent got it right

The honesty footer, `C130`, carries the reason on the screen. It exists because a person looking at
a green panel will otherwise infer the claim the studies do not support.

### The set, as drawn

Five rows, and each is a different relationship. The point of the screen is that these five are not
five copies of one thing.

File | Relationship | State | Which tools read it
`AGENTS.md` | the source | ok | Claude Code, Codex, Cursor, Jules, Amp, opencode, Zed and Warp
`CLAUDE.md` | a one-line import of the source | ok | Claude Code
`.github/copilot-instructions.md` | a copy, in step | ok | the Copilot coding agent
`.cursor/rules/style.mdc` | a copy, drifted | warn | Cursor
`GEMINI.md` | missing | off | the Gemini command-line tool

- **The plan records `AGENTS.md` as used by over 60,000 projects**, which is why it is the source
  rather than one format among five.
- **An import beats a copy, and the tool teaches the import.** All six of our own dual-file
  repositories use the import, which is `[O]` from the plan.
- **A copy exists only where the tool cannot read an import.** The drift card says so on the row it
  applies to: Cursor does not read a plain markdown file in that folder, so that one has to be a
  copy.
- The filter counts the source as linked. Two linked, two copies, one missing, five in all.

### The four checks, and their evidence

Every check states the evidence beside it, so a person can disagree with it.

Check | State | Evidence shown
Under every published size limit | ok | the word count, the byte size, and the cap the tool publishes
Setup commands present | ok | which commands were found
Claims unverified since a date | warn | the line numbers, and how long since anyone ran them
Rules a linter already enforces | warn | the line range, which linter, and that they cost tokens every session

**The last check is the one that earns the screen.** It finds text that costs tokens in every
session and changes nothing, which is the measured cost the research names.

## Data contract

What | Direction | Port or store | Shape | When
The set | in | `InstructionSetReader.scan(projectId)` | one record per known instruction file, with its relationship | on mount, and on any write to a member
File bytes | in | `DocumentReader.open(path)` | bytes | per member, on scan
Published caps | in | a shipped table of tool limits | tool, cap, and where it was read | on mount
Drift | in | derived, by comparing a copy to its source | a line delta | on scan
Checks | in | `CheckRunner.run(bytes, instructionRules)` | findings | on scan
Add an import | out | `DocumentWriter.create()` | the one-line import file | on `C085`
Regenerate | out | `DocumentWriter.splice()` | the copy's full range, replaced from the source | on `C135`, after a confirmation
Tidy | out | `LlmClient.generate()` then the change queue | a proposal, never a write | on `C061`

- **`InstructionSetReader` is `specified, not built`.** Nothing under `src/modules/` scans a project
  for instruction files today.
- **The caps table is shipped data, not a guess.** Each row records where the number was read, so a
  stale cap is findable rather than invisible.
- **Tidy produces a proposal.** It goes through the change queue like every other AI edit, and S20
  accepts or rejects it span by span.

## Keyboard and focus

- The panel opens with focus on the filter.
- Up and down move through the file rows; Enter opens the focused file.
- The drift card's two buttons are one Tab apart, with Diff first, because reading before replacing
  is the order that avoids losing work.
- Regenerate never fires on Enter alone. It opens a confirmation that names what will be replaced.
- Escape closes the panel.
- The full map is `15-INTERACTION-AND-KEYBOARD.md`.

- The panel becomes the right drawer, reached from More.
- The file rows keep the full path. A truncated path is useless on this screen, because
  `.cursor/rules/style.mdc` and `.github/copilot-instructions.md` are told apart by their folders.
- The tool list on each row shortens to the first tool and a count of the rest.
- **The honesty footer stays in full.** It is the last thing that would be cut, not the first.

## What this screen must never do

- **Never claim that tidying an instruction file makes an agent better at its job.** Two studies
  measured no gain in task success and one measured over 20 per cent added cost. The screen reports
  correctness, not effectiveness.
- **Never show one file as though it were the whole set.**
- **Never present a copy as equivalent to an import.** An import cannot drift; a copy can, and the
  screen exists partly to say which is which.
- **Never create a copy where the tool supports an import.**
- **Never regenerate over hand edits without refusing first.**
- **Never state a size cap without naming the tool it belongs to.** The caps are per tool, and a
  number with no owner is worse than no number.
- **Never mark a row ok when its cap is unknown.**
- **Never let Tidy write directly to a file.** It proposes, and the queue decides.
- **Never drop the honesty footer for space, on any surface.**
- **Never use an emoji for a row's state.**
