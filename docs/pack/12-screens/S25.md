# S25. Desktop app

> **Ids invented here.** This file reserves `C250` to `C259`, `E250` to `E259` and `A250` to
> `A259`, on the rule that the two digits after the letter are the screen number. Copy ids are
> namespaced `K.s25.*`. A component owned by another screen is cited by that screen's id.
>
> **Which registers exist.** `16-COPY-DECK.md`, `15-INTERACTION-AND-KEYBOARD.md` and
> `53-PRICING-AND-ENTITLEMENTS.md` exist and are cited by their real ids.
> `14-COMPONENT-INVENTORY.md`, `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md`,
> `55-MEASUREMENT-AND-EVENTS.md` and `56-OPEN-DECISIONS.md` are being written in parallel and did not

> it carries its section as well as its line. The section is the durable half.

## Purpose

Work on cloud projects and folders on this machine in one tree, with every document a real file on
disk.

## This screen is two things

Surface | What it is | Where it is drawn
The application window | The workspace running in the desktop shell, with cloud projects and local folders in one tree | `docs/mvp0/screens/gen.mjs:1468`, a window frame over a desktop
The download page | A page on the web that names the three platforms and their state, and emails the link | `docs/mvp0/screens/gen.mjs:1479`, drawn as the phone view

Both belong to S25 because they answer one question from two sides: what the download gives, and what
it looks like once it is installed.

## Entry and exit

Direction | How | Route or control

In | The desktop card on S24, offline in the browser | S24

## Data contract

What | Direction | Port or store | Shape | When
Local folder tree | read | The file system, through the desktop shell | Paths and bytes on disk | On open, and on change
Cloud project tree | read | `ProjectFiles.list(projectId)` | Paths and bytes | On open, and on sync
Document body | read and write | The file on disk for a local file, the splice engine for a cloud one | Bytes | On open and on save
Save marker | derived | Which store the file came from | Saved, or saved to disk | On each save
Agent writes | read | The watched folder | A file changed on disk by something that is not us | Whenever it happens, into the queue on S20
Entitlement | read | `limitsFor(account)` | `features.desktop`. **The document cap does not apply here** | On open
Download links | read | `Releases.latest()` | One artefact per platform, with its state | On the download page

**The shell exists and the rest does not.** `src-tauri/` is a real Tauri project at `0af3c90`, with
`tauri.conf.json` naming the product and the bundle identifier `ai.sgnk.md`. **The unified tree, the
files-on-disk path, the watched folder and the local model are specified, not built.**

**The bundle identifier does not change.** It is named as unchanged in `AGENTS.md` section 8,
alongside the local persistence keys, because changing it makes the installed application a different
application to the operating system.

**What the desktop build gives**, at `docs/mvp0/PRODUCT-PLAN.md` section 12, at line 1081: files on
disk, no document limit, fully offline, and agents can read the folder. **It is the one we promote,
and the web app stays**, at section 12, line 1082.

## Actions

Action | Trigger | What happens | Failure behaviour | Event id
Open the application | Launching it | The unified tree loads from both stores. Local files load first, because they need no network | Cloud unreachable, so `E250` and local folders still open | `desktop.opened`
Add a local folder | The tree head control | A directory is chosen and appears as its own group | Permission refused by the operating system, so `E251` names the folder and the setting | `desktop.folder.added`
Edit a local file | Typing | The bytes are written to disk on save, through the same splice rule | Splice ambiguous, so it refuses and the file is untouched | `desktop.file.saved`
Meet an agent's write | A watched file changing under us | The change enters the queue on S20, never the document | File no longer parseable, so `E252` names it and the queue item is held | `desktop.agent.write.queued`
Download from the page | The email control | The link is emailed. Nothing downloads in the page itself | Address not deliverable, so `E253` | `desktop.link.emailed`
Read a platform row | Opening the page | Each row states its state and its reason | none | `desktop.platforms.viewed`
Update the application | The shell's own update check | A new version is offered | Signature check fails, so `E254`, and the update is refused rather than installed | `desktop.update.offered`

**`E254` refuses rather than warns.** An update whose signature does not verify is not offered with a
caution. It is refused.

## States

State | When | What is shown | What the person can do
first-run | The first launch after installing | The tree, empty of local folders, with one line offering to add one | Add a folder, or open a cloud project.
empty | No cloud projects and no local folders | The same as first-run | Add, or import.
loading | Trees are being read | Local groups appear first, cloud groups after | Open a local file.
partial | Local in, cloud still syncing | Local files are fully editable. Cloud groups show their shape | Work locally.
offline | No connection | Local files are unaffected. Cloud projects show their last synced copy and queue changes | Everything, including AI through the local model.
unauthorised | Signed out | Local folders stay open and editable. Cloud projects are hidden until sign-in | Work locally, or sign in.
over-cap | n/a. **The document cap does not apply on the desktop** | n/a | n/a.
AI-unavailable | Every provider refused and no local model is installed | The same refusal as S32, with the local model offered as the remedy | Install the local model, or retry.
conflict | A file changed on disk and in the cloud | S31. Both versions kept, nothing merged | Keep one, keep both, or propose a merge.
error | A disk write failed | `E255`, at once, naming the path and the reason | Free space, fix permissions, retry.
degraded | A watched folder is very large | Watching is narrowed to the folders in the tree, and says so | Narrow the folder, or stop watching.

## Keyboard and focus

key | does
Everything the web does | Unchanged. The same editor, the same bindings
Command Shift Space | Quick capture, which is a global shortcut and exists only here, per S26
The platform's own window chords | Owned by the operating system and never rebound

**Focus on launch is the document that was open when the application last closed.** Restoring the
previous state is the platform expectation, and it is the plan's own reasoning on the home screen.

**The desktop build may claim global shortcuts, and the web build may not.** That asymmetry is
recorded in `15-INTERACTION-AND-KEYBOARD.md`, which marks the quick-capture chord as desktop only
because a web page cannot claim a system-wide chord.

## Responsive

- **The application window has a minimum width** below which the tree and the rail become drawers, the
  same breakpoint the web uses.
- **The download page is the phone surface.** A phone cannot run the application, so the page names
  the platforms and emails the link instead of offering a download that would fail.
- **The phone page keeps the bottom bar**, because it is a page inside the web app.

## Desktop differences

This screen **is** the desktop difference. What it adds over the web, in one table.

Capability | Web | Desktop
Files on disk | No. Bytes live in the cloud store | Yes
Document cap | `limits.docs.cloud` applies | Does not apply
Offline AI | Refused, per S24 | A local model, with nothing leaving the machine
An agent editing the file | Only through a connection or a token | A watched folder, feeding the queue on S20
Quick capture | Absent. A web page cannot claim a global chord | A global shortcut, per S26
Protocol handler | Absent | Registered, which is what S18's open-in bar detects

## What this screen must never do

- **Never apply a file changed on disk straight into the document.** It goes to the queue.
- **Never enforce the cloud document cap** on a local folder.
- **Never change the bundle identifier.**
- **Never install an update whose signature did not verify.**
- **Never show a Windows download before there is a signed artefact.** Say why it is not there.
- **Never claim Linux is signed.** It is unsigned by choice, and the row says so.
- **Never hold the only copy of a cloud document** on this machine without syncing it.
- **Never open a provider consent screen inside the application window.** Use the system browser.
