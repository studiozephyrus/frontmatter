## AREA: Document-format package ecosystems: precedent, registry design, absence semantics, security surface, and vendor-hosting 
**HEADLINE:** Only two document formats ever acquired a real package ecosystem — LaTeX (7,021 CTAN packages) and Typst (1,481 packages in ~3 years) — and both are Turing-complete programming languages; every markdown-adjacent system that tried (Quarto, Sphinx, MkDocs, Pandoc) deliberately refused document-declared registry resolution, and the single design variable that determines whether MDMAX inherits npm's threat model is not the registry but whether a library is host code or sandboxed document-language code.

**FINDINGS:**

- **[primary-read]** CTAN is the only document-format package ecosystem at true scale: 7,021 packages across 610 topics, governed by five named volunteers, with no automated review and no version solver.
  - EVIDENCE: Fetched live 2026-07-31T22:45Z: `curl https://ctan.org/json/2.0/packages` → 7,021 entries; `https://ctan.org/json/2.0/topics` → 610. TeX Live tlpdb (`mirror.ctan.org/systems/texlive/tlnet/tlpkg/texlive.tlpdb.xz`, 20.4 MB decompressed) has 8,079 `name` entries, 7,064 `category Package`, 5,139 excluding binary/doc/src variants. Governance, from CTAN's own uploader addendum: "the following persons (in alphabetical order) take care of CTAN: Erik Braun (upload management and system administration), Vincent Goulet (upload management), Manfred Lotz (upload management, programming, system administration), Gerd Neugebauer (web developer), Petra Rübe-Pugliese (upload management). All these people are acting as volunteers in their spare time". Policy is metadata-driven: README mandatory, license metadata mandatory, ASCII filenames, no whitespace/shell-metacharacters in filenames, uniqueness of filenames approached as an ideal.

- **[primary-read]** LaTeX has no version resolution at all — only a date comparison that emits a WARNING, never an error. This is the precise mechanical root of LaTeX's famous reproducibility pain, and MDMAX must not copy it.
  - EVIDENCE: Read `latex3/latex2e/base/ltclass.dtx` (develop branch, 154,501 bytes). Line ~2475: `\@ifl@ter\@currext{\@currname}{#3}{}` then `\@latex@warning@no@line{You have requested,\on@line, version `#3' of \@cls@pkg\space \@currname, but only version `\csname ver@\@currname.\@currext\endcsname' is available}` — a warning macro, not `\@latex@error`. Resolution is by DATE ordering only (`\@ifl@ter`), not semver. LaTeX added a rollback mechanism in 2018 (`\DeclareRelease{name}{from-date}{filename}`, ltclass.dtx §'Package/class rollback mechanism', changes v1.2d 2018/02/18) — but it is opt-in per package and even a bad rollback date is downgraded to a warning (line 3825: "Make suspicious rollback a warning not error: github issue 43").

- **[primary-read]** LaTeX's MISSING-package behaviour is a hard interactive error that halts the run — the opposite of silent degradation.
  - EVIDENCE: `latex3/latex2e/base/ltfiles.dtx`, `\gdef\@missingfileerror#1#2{\typeout{^^J! LaTeX Error: File `#1.#2' not found.^^J^^J Type X to quit or <RETURN> to proceed,^^J or enter new name. (Default extension: #2)^^J}\message{Enter file name: }...}`. In batchmode (`\batchmode\read-1 to`) it ends the TeX run. Note the asymmetry MDMAX should NOT replicate: missing = fatal, wrong version = warning.

- **[primary-read]** Typst is the reference minimum-viable design and the only modern proof a document format can bootstrap a registry cheaply: 1,481 distinct packages / 4,425 name:version rows as of today, built by one person in one week, with no registry service — a git repo, a GitHub Action, and a CDN.
  - EVIDENCE: Live fetch 2026-07-31T22:45Z of `https://packages.typst.org/preview/index.json` (2,060,620 bytes): 4,425 entries, 1,481 distinct `name` values; newest `updatedAt` = 2026-07-31T14:44:40Z (index is live, not stale). Vendor design doc (typst.app/blog/2023/package-manager, 2023-06-30, Laurenz Mädje): "we took a step back and sketched out a design for a minimum viable package manager that a single person could build in a week"; "Submitting a package means making a pull request to our package repository with the full contents of the package"; "The package repository has a GitHub action that builds a tar.gz archive for each package and an index.json ... then uploads the packages and index to https://packages.typst.org/preview, which is served through a CDN"; "Won't get much simpler than serving a bunch of tar.gz files through a CDN".

- **[primary-read]** Typst's five load-bearing registry invariants — namespacing with a user-owned escape hatch, mandatory full version pinning, post-publish immutability, on-demand download, permanent offline cache — together give reproducibility with NO lockfile and NO solver. This is directly transplantable to MDMAX.
  - EVIDENCE: typst/packages README: "A package that is stored in `packages/preview/{name}/{version}` ... will become available in Typst as `#import "@preview/{name}:{version}"`. You must always specify the full package version." Local namespace: "You can create an arbitrary `{namespace}` ... Store a package in `{data-dir}/typst/packages/local/mypkg/1.0.0` ... Import from it with `#import "@local/mypkg:1.0.0": *`. Packages in the data directory have precedence over ones in the cache directory." Offline: "Importing a cached package does not result in network access." Immutability (typst/packages docs/README.md §'Fixing or removing a package'): "Once submitted, a package will not be changed or removed without good reason to prevent breakage for downstream consumers. By submitting a package, you agree that it is here to stay." Blog: "Reproducibility is ensured through two factors: We do not allow removal or change of packages after submission ... Every import must specify the full package version. While this is a bit inconvenient, it means that we don't need a manifest or lock file for reproducibility." Manifest requires only `name`, `version` ("full major-minor-patch triple", SemVer), `entrypoint`; `compiler` = minimum compiler version.

- **[primary-read]** Typst deliberately skips integrity verification — there are NO checksums on downloaded packages. This is the one gap MDMAX should close, and it is cheap.
  - EVIDENCE: `typst/typst` `crates/typst-kit/src/packages.rs` (main, 18,229 bytes), lines ~268-272, verbatim source comment: "This means that we do not check the integrity of an existing moved package, just like we don't check the integrity if the package directory already existed in the first place. If situations with broken packages still occur even with the rename safeguard, we might consider more complex solutions like file locking or checksums." Trust is entirely in TLS-to-CDN plus the immutability policy. No hash appears in `typst.toml` (docs/manifest.md fields: name, version, entrypoint, authors, license, description, homepage, repository, keywords, categories, disciplines, compiler, exclude — no digest field).

- **[primary-read]** Typst's WASM plugin contract is the exact security model MDMAX should copy: non-WASI, byte-buffers only, no ambient authority, purity required. It is materially different from every host-code plugin system.
  - EVIDENCE: typst.app/docs/reference/foundations/plugin: "For security reasons, plugins run in isolation from your system. This means that printing, reading files, or similar things are not supported." "To run as a plugin, a program needs to be compiled to a 32-bit shared WebAssembly library." On WASI: "Many compilers will use the WASI ABI by default or as their only option (e.g. emscripten), which allows printing, reading files, etc. This ABI will not directly work with Typst. You will either need to compile to a different target or stub all functions." Protocol: exported fn takes n 32-bit integer length args, calls `wasm_minimal_protocol_write_args_to_buffer(buf.ptr)`, calls `wasm_minimal_protocol_send_result_to_host`, returns 0 = success / 1 = UTF-8 error message. Purity: "given the same arguments, it must always return the same value ... Typst might cache the results and call your function only once. Moreover, Typst may run multiple instances of your plugin in multiple threads, with no state shared between them." Honest caveat in the same doc: "Typst does not enforce plugin function purity (for efficiency reasons)" — isolation is ENFORCED, purity is only a CONTRACT. Non-plugin package code is also confined: "Within a package, everything is encapsulated: Package code can only read files in the package and absolute paths are resolved relative to the package root" (Typst blog).

- **[primary-read]** Racket's #lang is the best-designed resolution scheme in the corpus and its grammar is deliberately crippled — a lesson directly applicable to how MDMAX should spell an import line.
  - EVIDENCE: Racket Guide §17.3.1 (docs.racket-lang.org/guide/hash-lang_syntax.html), verbatim: "the syntax of language is far more restricted than a module path, because only a-z, A-Z, 0-9, / (not at the start or end), _, -, and + are allowed in a language name. These restrictions keep the syntax of #lang as simple as possible. Keeping the syntax of #lang simple, in turn, is important because the syntax is inherently inflexible and non-extensible; the #lang protocol allows a language to refine and define syntax in a practically unconstrained way, but the #lang protocol itself must remain fixed so that various different tools can 'boot' into the extended world." **RECOMMENDATION:**
(a) IS THERE A VIABLE PATH TO CHANGING COMMONMARK? For a new construct: NO. Evidence, not opinion: zero net new conformance examples between 0.30 (2021-06-20) and 0.31.2 (2024-01-28); the entire 0.31 changelog is typos and link fixes; 81 of 1,848 commits since 2020 with 44% of those by one person; no CONTRIBUTING/GOVERNANCE file anywhere in the repo; the 1.0 blocker list opened 2015 still says "[6 remaining]" and was last edited 2019; the two extension threads MDMAX cares about have run 316 posts over a decade and are still open; two IETF principals offered to formalize the spec and got no maintainer reply in four years; and the spec's own author built djot in 2022 to obtain attributes and generic containers rather than amend CommonMark. Do not spend a single week on this. There IS a narrow open path — clarification and bug-fix PRs still merge from outside contributors (e.g. #802 emphasis algorithm, 2025-05-10). Use it only if MDMAX finds a genuine ambiguity worth fixing; it will never carry a feature.

(b) THE ACTUAL MECHANISM — repeatable playbook, with the preconditions that made alerts, mermaid and frontmatter succeed:
  P0. CARRIER PRECONDITION: the construct must be already-valid CommonMark that degrades to readable prose in a non-supporting parser. Mermaid = fenced-code info string. Alerts = blockquote whose first line is literal text. This is exactly what jgm advised in 2015 ("impose some conventions on existing syntax... your content would degrade nicely if the extension isn't enabled") and it is the single non-negotiable. Anything requiring a grammar change has a 0-for-10-years track record.
  P1. REFERENCE IMPLEMENTATION + EXECUTABLE CONFORMANCE SUITE, shipped before any advocacy. CommonMark's one genuinely successful artifact is its 652 embedded examples; that is why 20+ parsers agree on the core.
  P2. CORPUS-YEARS BEFORE ADVOCACY. Alerts: 8.0 years inside Microsoft Learn. Mermaid: 7.2 years on npm. Frontmatter: 17.8 years since Jekyll. This is the same bar TC39 codifies as Stage 4 ("significant in-the-field experience") and WG21's template demands verbatim ("How widespread is its use? How long has it been in use?"). Do not shorten this by arguing; shorten it by generating corpus.
  P3. ONE DOMINANT RENDERER ADOPTS. This is the phase change, and it is the step MDMAX will fail by default. GitHub did it for alerts and mermaid; Jekyll-and-successors did it for frontmatter. No spec body was involved at any point in any of the three.
  P4. SHIP THE PORTS YOURSELF, ON ANNOUNCEMENT DAY. After GitHub's alerts announcement, five mutually incompatible npm plugins appeared within five months — and three of them landed BEFORE GA, meaning the ecosystem keys off a credible announcement, not a release. Publish MDMAX plugins for remark/rehype, markdown-it, marked and markdig simultaneously, or you will get five forks of your own syntax.
  P5. DOCUMENT IN USER-FACING DOCS, NOT A SPEC. GitHub documents alerts only in GitHub Docs; the GFM spec has said 0.29-gfm since 2019-04-06 and mentions alerts, mermaid, math and footnotes exactly zero times. The spec is decorative. Adoption is the artifact.
  MDMAX's honest mitigation for P3: it is not GitHub. The two realistic substitutes are (i) be the renderer for a corpus you fully control and publish at scale, and (ii) target the LLM/agent-tooling layer, which is currently the only place a new dominant markdown renderer is being minted.
