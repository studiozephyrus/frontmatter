# S06. AI writing box

> The founders called this screen confusing on 18 September. Everything below exists to make one
> thing unambiguous: what is about to be touched.

> **Ids invented here.** `14-COMPONENT-INVENTORY.md`, `16-COPY-DECK.md`,
> `17-ERROR-AND-REFUSAL-CATALOGUE.md`, `19-ACCEPTANCE-CRITERIA.md`,
> `55-MEASUREMENT-AND-EVENTS.md` and `56-OPEN-DECISIONS.md` are being written in parallel and did
> not exist when this file was written. Ids follow `65-CONVENTIONS.md` section 3 on a stated
> scheme derived from the screen number: components `C060` to `C069`, errors `E060` to `E069`,
> acceptance `A060` to `A069`. A component owned by another screen is cited by that screen's id.
> Copy ids are namespaced `K.s06.*`, so they cannot collide.

## Purpose

Ask for writing in plain words, and never leave a doubt about which document or idea the answer
will land in.

## The founders' instruction, and the rule it produced

`docs/mvp0/SCREEN-CHANGES-2026-09-18.md:59` to `:63`, all `[Z]`:

- Markdown mode is fine. The AI writing box is confusing.
- It must be unambiguous whether the user is editing a document.
- Placement follows the content. If the documents sit below, the box opens below or to the right,
  whichever fits.
- If the user is working on an idea, that context appears and stays.

Section 8.3 of the same document turned that into three rules, and this file carries all three.

**The rule, stated once.** The box names its target on its own first line, always, in every state,
on every surface, including the phone. There is no compact form that drops it.

### The target line, in its three forms

These are the three states the plan names. A fourth does not exist; if the product cannot say
which of the three it is in, the box does not open.

Form | What the line says | When
Writing | writing a new document, then the file name | the open document is empty and unnamed
Editing | editing, then the file name, and the selected range when there is one | a document is open with bytes in it
Idea | the idea, then its name | an idea is in progress

- **Change is one click away**, on the same line, and it opens a target picker rather than
  guessing.
- **The selected range is shown when there is one.** A person who selected three paragraphs sees
  that they selected three paragraphs, before they spend a credit.
- **When an idea is in progress the line is pinned.** It does not scroll away with the content, and
  it survives the box being scrolled internally.

### Where the box opens

`docs/mvp0/SCREEN-CHANGES-2026-09-18.md:61` says placement follows the content.

Condition | Where the box goes
There is room below the content | below it, left-aligned to the content column
There is not room below | to the right of the content
Neither fits, which is the phone | a bottom sheet, full width
An idea is in progress | the same rules, with `C067` pinned to the top of the box

- It anchors to the **content**, not to the viewport corner and not to the button that opened it.
- It never covers the selection it is about to change. If the only fit would cover the selection,
  the content scrolls rather than the box moving on top of it.
- It closes on Escape and on a click outside, and both leave the document untouched.

## Data contract

What | Direction | Port or store | Shape | When
Current target | in | the editor's own state | `{kind: writing \| editing \| idea, name, range?}` | on open, and on every selection change
Credit balance | in | `LedgerReader.balance()` | used against the cap | on open, and after every call
Provider chain state | in | `ModelRouter.status()` | which providers are up | on open
The request | out | `LlmClient.generate({prompt, system})` | a string result | on send
The result | in | the same call | text, never applied directly | on return
Accept | out | `DocumentWriter.splice()` | a byte range and its replacement | on Accept only
Reject | out | nothing is written | n/a | on Reject
Ledger entry | out | `LedgerWriter.append()` | account, kind, delta, model, cost | on a call that returned
Draft prompt | out | the device draft store | the typed string, per document | on every keystroke, debounced

- `LlmClient` is real and lives at `src/modules/ai/application/ports.ts`. It has one member,
  `generate`, taking `{prompt, system?, speedFirst?}` and returning `Promise<string>`.
- **`ModelRouter`, `LedgerReader` and `LedgerWriter` are `specified, not built`.** The plan's
  section 14 defines the chain and the routing they would implement.
- **A ledger entry is written when a call returns, not when Accept is pressed.** The call cost us
  money whether or not the person kept the result, and the plan's data model makes ledger entries
  append-only.
- **Nothing is written to the document on the result.** The write happens on Accept and is a splice.

## States

State | When | What is shown | What the person can do
first-run | the first time the box opens on this account | the box, plus one line saying what a credit is | ask, or close
empty | the prompt is empty | the box with the send control disabled | type, or pick a chip
loading | the call is in flight | the target line, the prompt, and progress on the send control | cancel; nothing has been written
partial | the result is streaming | the proposal so far, with Accept disabled until it completes | wait, or cancel
offline | no network | the box opens and says the chain is unreachable | close; on the desktop the local model takes over
unauthorised | the role cannot edit this document | the box refuses to open and says the role | comment instead, on S05
over-cap | no edit credits left | the box opens, the send control is disabled, `E061` names the reset date | wait for the reset, top up, or use the desktop
AI-unavailable | every provider refused or timed out | `E060`: the document is untouched, nothing was charged, and each provider's state is listed | retry, or open S32
conflict | the target document has an unresolved conflict | the box refuses to open on that target | resolve on S31 first
error | the call threw | the named error, the prompt kept, the document untouched | retry, or change the prompt
degraded | the chain is on a slower fallback | the box works, and the foot names the provider | ask; it is slower, not worse

**Every failure state says the document is untouched.** That sentence is the product, and it is not
optional copy.

## Keyboard and focus

- On open, focus moves into the prompt field. The target line is read first by a screen reader,
  because it is the first element in the box's accessible order.
- Command Enter sends. Enter inserts a newline, because a prompt is prose and people press Enter in
  prose.
- Escape closes and returns focus to whatever had it before, usually the caret in the document.
- Tab moves from the prompt to the chips as one composite stop, then to the send control.
- On a result, focus moves to Accept, and Reject is one Tab away. Neither is activated by Enter
  alone without focus.
- The box is a focus trap while open, and the trap releases on Escape.

## Responsive

- The box becomes a bottom sheet at phone width, full width, rising over the document.
- **The target line survives.** It is the one element that is never dropped for space; the chips
  reduce from four to three before the target line loses a single word.
- The start-from row is dropped on the phone. Those three are reachable from S02 and from the tree.
- The cost foot shortens to the credit count and keeps the Get more link.
- The AI item in the bottom bar is lit while the sheet is open.

## Desktop differences

- When the network chain is unavailable, the desktop build offers a local model rather than
  `E060`. The plan's section 14 lists the models that fit an 8 GB machine.
- A local run costs no credit, and the cost foot says so instead of counting one.
- Nothing leaves the machine on a local run, and the foot says that too.

## What this screen must never do

- **Never open without naming its target.** If the target cannot be determined, the box does not
  open, and that refusal is correct.
- **Never shorten the target line away** for space, on any surface, in any state.
- **Never let an idea's context scroll out of view** while that idea is in progress.
- **Never write to the document on the result.** Accept writes, and Accept is a splice.
- **Never apply a change without a click**, which is the switching driver the plan names at
  21 mentions.
- **Never make Reject quieter than Accept.**
- **Never charge for a call that did not return**, and never say a credit was spent when the ledger
  has no entry.
- **Never anchor to the viewport corner** and call it following the content.
- **Never show a confidence percentage.** The plan's rule is to show alternatives rather than
  confidence.
- **Never block typing in the document** because the box is open.
- **Never use an emoji on a chip or a control here.**

## Limits of this file

- **Not assessed:** the target picker's own surface. It is named and specified only by behaviour.
- **Not assessed:** streaming. The plan's performance target is first token under three seconds, and
  this file specifies the partial state without specifying the transport.
- **Could not be verified:** that `LlmClient.generate` can carry a selection range. The port takes a
  prompt and an optional system string, so the range has to be composed into the prompt.
  `UNVERIFIED:` whether that is enough for a byte-exact splice on return.
- **What would falsify this file:** a decision to apply a result on arrival with an undo, which
  would reverse the accept-first rule that the rest of the product depends on.
